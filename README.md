# 学校智能排课系统

> 面向 K-12 国际学校的智能排课解决方案，基于 Google OR-Tools CP-SAT 约束满足求解器

---

## 项目概述

本系统是专为双语/国际学校设计的智能排课平台，核心解决**分层教学**、**早晚班管理**、**场地资源分配**等复杂排课问题。

### 核心特性

| 特性 | 说明 |
|------|------|
| **CP-SAT 求解器** | 基于 Google OR-Tools 的约束满足求解，确保找到可行解或报告无解原因 |
| **三层约束体系** | 物理硬约束 / 严格约束 / 可调软约束，权重和优先级可配置 |
| **分层教学排课** | 支持跨年级分层和合班，自动保证同层同时上课 |
| **连堂课支持** | 每周恰好 1 次连堂 + 剩余单节，不跨午休 |
| **方案管理** | 自动保留最近 6 批排课结果，支持跨批次对比 |
| **求解诊断** | 无解时逐层放松约束定位冲突源，给出可读报告 |
| **多视图展示** | 班级、教师、教室多维度课表查看 |
| **拖拽调课** | 可视化课表编辑，支持拖拽调换课程 |
| **教研组组会** | 自动为教研组找到连续 2 节空闲时段 |
| **管理干部会议** | 小学/中学管理干部指定会议时间段不排课 |

### 适用场景

- **班级规模**: 28 个班级（国际班 + 综素班）
- **年级范围**: PK、KG、G1-G11
- **教师规模**: 50-80 人（支持小中贯通）
- **每周课时**: 周一至周四 9 节 + 周五 7-8 节（G8-G9 周四加 10-11 节）

## 快速开始

### 环境要求

- Python 3.10+
- Node.js 18+
- PostgreSQL 14+
- Google OR-Tools (`pip install ortools`)

### 后端启动

```bash
cd backend

# 创建虚拟环境（首次）
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux/Mac

# 安装依赖
pip install -r requirements.txt

# 配置数据库（编辑 .env 文件）
# DATABASE_URL=postgresql://user:pass@localhost/schedule_db

# 启动服务
python -m uvicorn app.main:app --reload
```

访问: http://localhost:8000/docs (API 文档)

### 前端启动

```bash
cd frontend

# 安装依赖（首次）
npm install

# 启动开发服务器
npm run dev
```

访问: http://localhost:3000

## 约束体系

系统采用三层约束架构，求解器在构建模型时依次添加：

### Tier 1: 物理硬约束（违反 = 无效解，不可关闭）

| 编号 | 约束 | 说明 |
|------|------|------|
| H1 | 课程必须排入 | 每个 session 恰好安排到一个槽位 |
| H2 | 教师无冲突 | 同一教师同一时刻最多上一节课 |
| H3 | 班级无冲突 | 同一班级同一时刻最多上一节课 |
| H4 | 场地容量上限 | 同一时段使用同类场地不超过物理容量 |

### Tier 2: 可配置业务约束（支持 Hard/Soft 模式切换）

| 编号 | 约束 | 默认模式 | 说明 |
|------|------|---------|------|
| R1 | 每日同科目上限 | Hard | 同一班级每天同一科目最多 2 节 |
| R2 | 主科优先上午 | Soft(8) | 语数英等主科优先排在上午 |
| R3 | 科目周内均匀分布 | Soft(6) | 避免同科目集中在某几天 |
| R4 | 艺体课避开第 1 节 | Soft(5) | 体育/美术/音乐不排第一节 |
| R5 | 场地使用分散 | Soft(4) | 需要场地的课程分散排列 |
| R6 | 早晚班教师约束 | Soft(3) | 晚班教师上午尽量不排课 |
| R7 | 会议/教研时间预留 | Soft(2) | 预留会议时段 |
| R8 | 教研组组会 | Hard | 同教研组教师每周 2 节连续空闲 |
| R9 | 管理干部会议 | Hard | 小学周一/中学周二下午管理干部不排课 |


## 常见问题

### Q: 排课报 INFEASIBLE 怎么办？

**A:** 系统会自动逐层放松约束并诊断冲突源。查看后端终端日志中的 `[诊断]` 部分，根据结论调整数据或将导致冲突的约束从 Hard 切换为 Soft。

### Q: 前端约束设置保存后排课没有生效？

**A:** 确认保存成功后，排课引擎会自动读取活跃的 `ScheduleConfig`。如果没有活跃配置，使用默认权重。

### Q: 修改了代码但不生效？

**A:**
- 后端: 确认 `--reload` 模式已启用
- 前端: Vite HMR 自动更新

### Q: 数据库字段不存在？

**A:** ORM 模型与数据库不同步。执行 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS ...`。

### Q: 如何部署到生产环境？

**A:** 参见 [部署与迁移指南](docs/部署与迁移指南.md)，推荐使用 Docker Compose 方式。
