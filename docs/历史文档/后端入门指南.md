## 一、什么是后端？

### 1.1 一个形象的比喻

想象一家餐厅：

```
┌─────────────────────────────────────────────────────────────────┐
│                         餐厅系统比喻                              │
├─────────────────────────────────────────────────────────────────┤

│      │                                                          │
│      ▼                                                          │
│   ┌─────────────┐                                               │
```

### 1.2 前端 vs 后端

| 方面 | 前端 (Frontend) | 后端 (Backend) |
|------|-----------------|----------------|
| **定义** | 用户能看到和操作的部分 | 用户看不到的服务器程序 |
| **运行位置** | 用户的浏览器中 | 服务器上 |
| **主要工作** | 展示界面、处理用户操作 | 处理数据、业务逻辑 |
| **技术** | HTML/CSS/JavaScript/Vue | Python/Java/Go + 数据库 |
| **比喻** | 餐厅的装修和菜单 | 厨房和食材仓库 |

## 二、前后端如何协作

### 2.1 通信方式：HTTP 请求

前端和后端通过 **HTTP 请求** 进行通信。你可以把它想象成写信：

```
┌──────────────────────────────────────────────────────────────┐
│                    HTTP 请求就像写信                          │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│   前端写的"信"（请求）：                                       │
│   ┌──────────────────────────────────────┐                   │
│   │ 收件人地址: http://localhost:8000    │ ← URL (去哪里)     │
│   │ 收件人姓名: /api/v1/teachers         │ ← 路径 (找谁)      │
│   │ 做什么事:   GET                      │ ← 方法 (干什么)    │
│   │ 附带资料:   page=1&limit=10          │ ← 参数 (带什么)    │
│   └──────────────────────────────────────┘                   │
│                                                              │
│   后端回的"信"（响应）：                                       │
│   ┌──────────────────────────────────────┐                   │
│   │ 状态: 200 OK                         │ ← 状态码 (成功/失败)│
│   │ 内容:                                │                   │
│   │ {                                    │                   │
│   │   "code": 200,                       │ ← JSON 格式数据    │
│   │   "data": {                          │                   │
│   │     "items": [                       │                   │
│   │       {"id": 1, "name": "张三"},     │                   │
│   │       {"id": 2, "name": "李四"}      │                   │
│   │     ]                                │                   │
│   │   }                                  │                   │
│   │ }                                    │                   │
│   └──────────────────────────────────────┘                   │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 四种常用 HTTP 方法

| 方法 | 作用 | 生活比喻 | 示例 |
|------|------|---------|------|
| **GET** | 获取数据 | 去图书馆借书 | 获取教师列表 |
| **POST** | 创建数据 | 往银行存钱 | 添加新教师 |
| **PUT** | 更新数据 | 修改快递地址 | 修改教师信息 |
| **DELETE** | 删除数据 | 注销账户 | 删除教师 |

### 2.3 实际的通信过程

```javascript
// 前端代码 - 发送请求获取教师列表

      'Content-Type': 'application/json'  // 告诉后端：我说的是JSON语言

  // 2. 后端处理请求，返回数据
```

## 三、后端的核心概念

### 3.1 分层架构

后端代码通常按照 **职责** 分成不同的层：

```
┌─────────────────────────────────────────────────────────────────┐
│                        后端分层架构                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   HTTP请求进来                                                   │
│        │                                                        │
│        ▼                                                        │
│   ┌──────────────────────────────────────────────────────────┐  │
│   │ 路由层 (Router / Controller)                              │  │
│   │ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━                             │  │
│   │ 职责: 接收请求，调用业务逻辑，返回响应                       │  │
│   │ 文件: router.py                                           │  │
│   │ 比喻: 前台接待员，把客人带到对应的处理人员那里               │  │
│   └───────────────────────────┬──────────────────────────────┘  │
│                               │                                 │
│                               ▼                                 │
│   ┌──────────────────────────────────────────────────────────┐  │
│   │ 业务逻辑层 (Service)                                      │  │
│   │ ━━━━━━━━━━━━━━━━━━━━━━                                    │  │
│   │ 职责: 处理复杂的业务规则，协调多个操作                      │  │
│   │ 文件: service.py (可选，简单项目直接在router中处理)         │  │
│   │ 比喻: 项目经理，决定事情怎么做                             │  │
│   └───────────────────────────┬──────────────────────────────┘  │
│                               │                                 │
│                               ▼                                 │
│   ┌──────────────────────────────────────────────────────────┐  │
│   │ 数据访问层 (CRUD / Repository)                            │  │
│   │ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━                           │  │
│   │ 职责: 与数据库交互，执行增删改查操作                        │  │
│   │ 文件: crud.py                                             │  │
│   │ 比喻: 仓库管理员，负责存取货物                             │  │
│   └───────────────────────────┬──────────────────────────────┘  │
│                               │                                 │
│                               ▼                                 │
│   ┌──────────────────────────────────────────────────────────┐  │
│   │ 数据模型层 (Models)                                       │  │
│   │ ━━━━━━━━━━━━━━━━━━━━━━                                    │  │
│   │ 职责: 定义数据结构，映射数据库表                           │  │
│   │ 文件: models.py                                           │  │
│   │ 比喻: 货物清单，定义每种货物有哪些属性                      │  │
│   └───────────────────────────┬──────────────────────────────┘  │
│                               │                                 │
│                               ▼                                 │
│   ┌──────────────────────────────────────────────────────────┐  │
│   │                     数据库                                 │  │
│   │                   PostgreSQL                              │  │
│   └──────────────────────────────────────────────────────────┘  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 每一层的代码示例

让我们以 **教师模块** 为例，看看每一层都做什么：

```python
# ========================================
# models.py - 数据模型层
# ========================================
# 定义"教师"在数据库中是什么样子

from sqlalchemy import Column, Integer, String

class Teacher(Base):
    """
    教师数据模型
    
    这个类定义了 teachers 数据库表的结构
    每一个属性对应表中的一列
    """
    __tablename__ = "teachers"  # 表名
    
    id = Column(Integer, primary_key=True)  # 主键，自动递增的唯一标识
    name = Column(String(50), nullable=False)  # 姓名，不能为空
    type = Column(String(2), default="CN")  # 类型：CN=中教，EN=外教
    department = Column(String(20))  # 学部：PRIMARY=小学，SECONDARY=中学
```

```python
# ========================================
# schemas.py - 数据验证层
# ========================================
# 定义前端发来的数据应该是什么格式

from pydantic import BaseModel, Field

class TeacherCreate(BaseModel):
    """
    创建教师时需要的数据格式
    
    前端发送的 JSON 必须符合这个格式，否则自动报错
    """
    name: str = Field(..., min_length=1, description="教师姓名，必填")
    type: str = Field(default="CN", description="教师类型")
    department: str = Field(default="PRIMARY", description="所属学部")
    
    # 这里的验证会自动进行：
    # - name 必须提供，且至少1个字符
    # - type 如果不提供，默认是 "CN"
```

```python
# ========================================
# crud.py - 数据访问层
# ========================================
# 封装所有数据库操作

from sqlalchemy.orm import Session
from .models import Teacher
from .schemas import TeacherCreate

def get_teachers(db: Session, skip: int = 0, limit: int = 100):
    """
    获取教师列表
    
    Args:
        db: 数据库会话（可以理解为数据库连接）
        skip: 跳过前面多少条（分页用）
        limit: 最多返回多少条
    
    Returns:
        教师列表
    """
    return db.query(Teacher).offset(skip).limit(limit).all()
    #      │               │              │           │
    #      │               │              │           └─ 执行查询，返回所有结果
    #      │               │              └─ 最多取 limit 条
    #      │               └─ 跳过前 skip 条
    #      └─ 查询 Teacher 表

def create_teacher(db: Session, teacher: TeacherCreate):
    """
    创建新教师
    
    Args:
        db: 数据库会话
        teacher: 教师数据（已经过验证）
    
    Returns:
        创建后的教师对象（包含自动生成的 id）
    """
    # 1. 创建教师对象
    db_teacher = Teacher(**teacher.model_dump())
    #                    │
    #                    └─ 把 TeacherCreate 转成字典，然后作为参数传给 Teacher
    
    # 2. 添加到数据库会话
    db.add(db_teacher)
    
    # 3. 提交到数据库
    db.commit()
    
    # 4. 刷新对象，获取数据库生成的 id
    db.refresh(db_teacher)
    
    return db_teacher
```

```python
# ========================================
# router.py - 路由层
# ========================================
# 定义 API 接口

from fastapi import APIRouter, Depends
from sqlalchemy.orm import Session
from .crud import get_teachers, create_teacher
from .schemas import TeacherCreate

router = APIRouter()

@router.get("/")  # GET /api/v1/teachers
async def list_teachers(
    page: int = 1,
    page_size: int = 20,
    db: Session = Depends(get_db)  # 自动获取数据库连接
):
    """
    获取教师列表
    
    这个函数会在用户访问 GET /api/v1/teachers 时被调用
    """
    skip = (page - 1) * page_size
    teachers = get_teachers(db, skip=skip, limit=page_size)
    return {
        "code": 200,
        "message": "success",
        "data": {"items": teachers}
    }

@router.post("/")  # POST /api/v1/teachers
async def add_teacher(
    teacher: TeacherCreate,  # FastAPI 自动从请求体解析并验证
    db: Session = Depends(get_db)
):
    """
    创建新教师
    
    前端发送 POST 请求，请求体是 JSON 格式的教师数据
    FastAPI 自动验证数据格式是否符合 TeacherCreate
    """
    new_teacher = create_teacher(db, teacher)
    return {
        "code": 200,
        "message": "创建成功",
        "data": new_teacher
    }
```

```
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 SQLAlchemy - ORM 框架

```
┌─────────────────────────────────────────────────────────────────┐
│ SQLAlchemy 是什么？                                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│ ORM = Object Relational Mapping（对象关系映射）                  │
│                                                                 │
│ 简单说：让你用 Python 代码操作数据库，不用写 SQL 语句             │
│                                                                 │
│ ┌────────────────────────────────────────────────────────────┐  │
│ │ 传统方式 - 写 SQL                                          │  │
│ │ ─────────────────────                                      │  │
│ │ cursor.execute(                                            │  │
│ │     "SELECT * FROM teachers WHERE type = 'CN'"             │  │
│ │ )                                                          │  │
│ │                                                            │  │
│ │ 问题：                                                      │  │
│ │ - SQL 是字符串，写错了 IDE 不会提示                          │  │
│ │ - 容易被 SQL 注入攻击                                       │  │
│ │ - 不同数据库 SQL 语法可能不同                               │  │
│ └────────────────────────────────────────────────────────────┘  │
│                                                                 │
│ ┌────────────────────────────────────────────────────────────┐  │
│ │ ORM 方式 - 写 Python                                       │  │
│ │ ────────────────────────                                   │  │
│ │ db.query(Teacher).filter(Teacher.type == "CN").all()       │  │
│ │                                                            │  │
│ │ 优点：                                                      │  │
│ │ - 代码即数据库结构，IDE 可以自动补全                         │  │
│ │ - 自动防止 SQL 注入                                         │  │
│ │ - 更换数据库只需改配置，代码不用动                           │  │
```

### 7.1 RESTful API 设计原则

```
┌─────────────────────────────────────────────────────────────────┐
│                     RESTful API 设计原则                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  REST = Representational State Transfer（表述性状态转移）        │

│  │ 资源命名规则                                                │ │
│  │ ─────────────                                              │ │
│  │                                                            │ │
│  │ ✓ 正确：使用名词复数                                        │ │
│  │   /api/v1/teachers       表示"教师"这个资源集合              │ │
│  │   /api/v1/teachers/1     表示 id=1 的教师                   │ │
```

## 八、常见术语表

| 术语 | 英文 | 解释 |
|------|------|------|
| API | Application Programming Interface | 应用程序接口，前后端通信的"语言" |
| REST | Representational State Transfer | 一种 API 设计风格 |
| HTTP | Hypertext Transfer Protocol | 网络通信协议 |
| URL | Uniform Resource Locator | 统一资源定位符，网址 |
| JSON | JavaScript Object Notation | 数据交换格式 |
| ORM | Object Relational Mapping | 对象关系映射 |
| CRUD | Create Read Update Delete | 增删改查 |
| 主键 | Primary Key | 唯一标识一行数据的字段 |
| 外键 | Foreign Key | 关联其他表的字段 |
| 事务 | Transaction | 一组操作，要么全成功，要么全失败 |
| 中间件 | Middleware | 请求到达处理函数前的"拦截器" |
| 路由 | Router | URL 到处理函数的映射 |
| 依赖注入 | Dependency Injection | 自动传入依赖对象的设计模式 |
| 异步 | Async | 非阻塞的执行方式，提高并发性能 |
| 会话 | Session | 一次数据库连接的上下文 |
| 迁移 | Migration | 数据库结构变更的版本管理 |
