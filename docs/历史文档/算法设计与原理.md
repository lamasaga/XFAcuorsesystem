## 一、核心思想：装箱子与大石头

### 1.1 问题本质
排课问题本质上是一个 **"资源分配问题"** 或 **"约束满足问题 (CSP)"**。

想象你有一个巨大的空箱子（**课表**），箱子里有很多小格子（**时间槽**，每周 5 天 × 9 节 = 45 个格子）。
你有即使堆积如山的物品（**课程**），你需要把这些物品塞进格子里，但要遵守很多规则：
1.  **形状匹配**：比如体育课不能排在刚吃完饭的午休后（格子形状不对）。
2.  **互斥**：张老师同一时间只能出现在一个格子里（不能分身）。
3.  **绑定**：G6的英语分层课，涉及7个班级7位老师，必须同时塞进同一个时间段（这就变成了一个巨大的组合物体）。

### 1.2 我们的策略：贪心策略 + 分治法

如果不讲策略，随机往里塞，肯定塞不下。我们采用 **"装罐子理论"**：

> 如果你想往罐子里装石头、鹅卵石和沙子，必须**先装大石头**，再装鹅卵石，最后倒沙子。

对应到排课系统：

| 优先级 | 类型 | 类比 | 为什么？ |
|:-----:|------|------|----------|
| **P0** | **分层走班课** | **大石头** | 涉及多个班级和老师，牵一发而动全身，最难安排，必须先占坑。 |
| **P1** | **场地受限课** | **鹅卵石** | 体育、美术等受场地容量限制（如体育场一次只能容纳4个班），稍后安排。 |
| **P2** | **普通行政班课** | **沙子** | 语数英等普通课，灵活性最高，最后填充到缝隙里。 |

## 二、数学模型（基础知识）

虽然我们用代码解决，但理解背后的数学描述有助于写出更严谨的逻辑。

### 2.1 集合定义

*   **教师集合** \( T = \{t_1, t_2, ..., t_n\} \)
*   **班级集合** \( C = \{c_1, c_2, ..., c_m\} \)
*   **时间槽集合** \( S = \{s_1, s_2, ..., s_{45}\} \) (周一第1节 到 周五第9节)

### 2.2 决策变量

我们要解出的答案，其实就是这样一个函数：
$$ X(c, t, s) = \begin{cases} 1, & \text{如果班级 } c \text{ 的老师 } t \text{ 在时间 } s \text{ 上课} \\ 0, & \text{否则} \end{cases} $$

### 2.3 约束条件（硬约束）

所谓的"硬约束"，就是**绝对不能违反**的规则。

**1. 教师不分身公式：**
对于任意时间 \( s \) 和任意教师 \( t \)，他/她只能在一个班级上课：
$$ \sum_{c \in C} X(c, t, s) \le 1 $$
*(翻译：所有班级在这个时间点占用该老师的次数之和，不能超过 1)*

**2. 班级不冲突公式：**
对于任意时间 \( s \) 和任意班级 \( c \)，该班级只能上一门课：
$$ \sum_{t \in T} X(c, t, s) \le 1 $$

**3. 分层同步公式（最难点）：**
如果一组班级 \( C_{layer} \) 属于同一个分层组，那么它们必须在相同的时间上课：
$$ \forall c_i, c_j \in C_{layer}, \quad X(c_i, t_a, s) = X(c_j, t_b, s) $$
*(翻译：大家要么都在这个时间上课，要么都不在)*

## 三、算法实现流程

我们将把这个复杂的数学问题，转化为以下几个代码模块。

### 阶段 1：构建"大石头" (Layers Module)

在开始排课前，我们需要先定义清楚哪些是"大石头"。
*   比如：G6年级英语分层，包含 G6-1 到 G6-4 四个班，需要 4 位英语老师。
*   这个结构体就是我们 Phase 2 要做的 `LayerGroup`。

### 阶段 2：寻找时间槽 (Slot Finder)

这是排课引擎的"眼睛"。当我们要安排一节课时，它负责扫描整个时间表。

**详细设计逻辑：**

输入：
*   **Subject**: 科目（如"数学"）
*   **Teachers**: 涉及的老师列表
*   **Classes**: 涉及的班级列表
*   **Duration**: 持续节数（通常为 1，连堂课为 2）
*   **Current Schedule**: 当前已排好的课表状态

处理流程（伪代码）：
```python
def find_slots(subject, teachers, classes, duration):
    available_slots = []
    
    # 遍历一周所有可能的起始时间点
    for day in 1..5:
        for period in 1..9:
            # 如果是连堂课，检查是否跨越了午休（比如第4节不能连第5节）
            if not is_valid_duration(period, duration): continue
            
            # 生成该时间段包含的所有时间槽（如 [周一第1节, 周一第2节]）
            slots_to_check = get_slots(day, period, duration)
            
            # 检查所有约束
            if check_hard_constraints(slots_to_check, teachers, classes):
                available_slots.append(slots_to_check)
                
    return available_slots

def check_hard_constraints(slots, teachers, classes):
    for slot in slots:
        # 1. 检查老师是否忙
        if any(teacher.is_busy(slot) for teacher in teachers): return False
        
        # 2. 检查班级是否忙
        if any(cls.is_busy(slot) for cls in classes): return False
        
        # 3. 检查老师不可用时间（如请假）
        if any(teacher.is_unavailable(slot) for teacher in teachers): return False
        
        # 4. 检查场地限制（如果是体育课）
        if subject.needs_venue:
             if not venue_manager.has_capacity(subject.venue_type, slot): return False
             
    return True
```

### 阶段 3：回溯搜索 (Backtracking)

当我们安排"分层课"遇到死胡同时（比如安排了前3层，第4层发现没老师有空了），我们需要**撤销**之前的操作，换个时间重试。这叫"回溯"。

**比喻**：这就好比走迷宫，碰到死路就退回到上一个路口，换条路走。

## 四、为什么你需要先做分层课程模块？

在明白了"装罐子理论"后，你就知道为什么我们需要先做 `layers`（分层课程）模块了。

因为分层课是**P0级优先级**。如果我们在数据库里连"哪些课是分层课"都不知道，排课引擎就无法识别出"大石头"，最后的结果就是大石头塞不进去，排课失败。

**分层课程的新特性**：
- 每个分层课程可以配置多个层级
- 每个层级可以指定一位任课教师
- 保存分层课程时，系统会自动生成对应的教学任务

所以，接下来的工作路径是：
1.  **完善后端数据结构**：让系统"认识"分层课程（Layers）和场地（Venues）。
2.  **编写核心工具**：写一个 `SlotFinder`（找空位的工具）。
3.  **编写调度器**：先写 `LayerScheduler`（专门排大石头的调度器）。
