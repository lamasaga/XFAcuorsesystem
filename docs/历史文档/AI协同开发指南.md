## 二、AI协同开发最佳实践

### 2.1 核心原则

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    AI协同开发三大原则                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   ┌─────────────────────────────────────────────────────────────────────┐  │
│   │  1️⃣  文档先行 (Documentation First)                                │  │
│   │  ───────────────────────────────────────────────────────────────── │  │
│   │  • 先写清楚"要做什么"，再让AI帮你"怎么做"                         │  │
│   │  • AI 可以完美理解 Markdown 文档                                   │  │
│   │  • 好的文档 = 好的 Prompt = 好的代码输出                           │  │
│   └─────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│   ┌─────────────────────────────────────────────────────────────────────┐  │
│   │  2️⃣  模块隔离 (Module Isolation)                                   │  │
│   │  ───────────────────────────────────────────────────────────────── │  │
│   │  • 每个模块独立，单个文件 < 300 行                                 │  │
│   │  • AI 对小文件的理解和修改更精准                                   │  │
│   │  • 降低上下文污染，减少错误传播                                    │  │
│   └─────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│   ┌─────────────────────────────────────────────────────────────────────┐  │
│   │  3️⃣  约定优于配置 (Convention Over Configuration)                  │  │
│   │  ───────────────────────────────────────────────────────────────── │  │
│   │  • 统一的命名规范、目录结构、代码风格                              │  │
│   │  • AI 可以学习并遵循这些约定                                       │  │
│   │  • 减少沟通成本，提高生成代码的一致性                              │  │
│   └─────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 Cursor Rules 配置

在项目根目录创建 `.cursorrules` 文件:

```markdown
# .cursorrules - Cursor AI 行为规则

## 项目背景
这是一个学校排课管理系统，包含排课、教务、学生、教室管理等功能。
技术栈: Vue 3 + FastAPI + PostgreSQL

## 代码规范

### Python (后端)
- 使用 Python 3.10+ 语法
- 遵循 PEP 8 规范
- 类型注解必须完整
- 函数文档字符串使用 Google 风格
- 异步函数使用 async/await

### Vue (前端)
- 使用 Composition API + <script setup>
- 组件名使用 PascalCase
- Props 必须定义类型
- 事件使用 kebab-case

### 命名规范
- 文件名: snake_case (Python), kebab-case (Vue)
- 类名: PascalCase
- 函数/方法: snake_case (Python), camelCase (JS)
- 常量: UPPER_SNAKE_CASE
- 数据库表名: snake_case (复数形式)

## 目录结构
- 后端模块: backend/app/modules/[模块名]/
- 前端模块: frontend/src/modules/[模块名]/
- 每个模块包含: models, schemas, crud, service, router (后端)
- 每个模块包含: api.js, routes.js, views/ (前端)

## 响应格式
API 响应统一使用:
```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

## 禁止事项
- 不要在代码中硬编码敏感信息
- 不要使用 any 类型 (TypeScript)

## 八、总结

### 核心要点

| 方面 | 策略 |
|------|------|
| **项目规模** | ~200文件，30,000-40,000行代码，AI辅助下6-10周完成 |
| **模块化** | 后端按领域分模块，前端按功能分模块，每个模块结构一致 |
| **文档先行** | 先写规格书，再让AI生成代码 |
| **小文件原则** | 单文件 < 300行，便于AI理解和修改 |
| **模板驱动** | 使用代码模板，保证一致性 |
| **验证流程** | AI生成 → 人工审查 → 测试 → 合并 |
| **冗余设计** | Git版本控制 + 文档 + 测试 + 数据备份 |

### AI协同效率提升关键

1. **好的文档 = 好的 Prompt** - 文档越清晰，AI输出越精准
2. **分而治之** - 大任务拆成小任务，逐步完成
3. **示例驱动** - 给AI一个好的参考，它能生成更多类似的
4. **迭代优化** - 不要期望一次完美，分步骤完善
5. **人机互补** - AI负责重复性工作，人负责设计和决策
