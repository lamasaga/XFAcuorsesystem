# 开发问题总结与经验教训

> 本文档总结了在排课系统开发过程中遇到的一系列问题，分析其根本原因，并提出改进建议。

## 一、问题清单与原因分析

### 1. 数据库字段不同步问题

**现象：**
- 后端返回 500 错误
- 前端显示 CORS 错误（实际是后端崩溃导致）
- 错误信息：`字段 subjects.applicable_grades 不存在`

**根本原因：**
- 在代码中添加了新的数据库字段（`applicable_grades`, `applicable_class_types`）
- 但没有同步更新数据库表结构
- SQLAlchemy ORM 模型与实际数据库表结构不一致

**教训：**
```
代码模型 ≠ 数据库表
修改 ORM 模型后，必须同步更新数据库！
```

---

### 2. CORS 跨域问题

**现象：**
- 控制台报错：`Access to XMLHttpRequest... has been blocked by CORS policy`
- 请求被重定向导致 CORS 头丢失

**根本原因：**
- FastAPI 默认会将 `/api/subjects` 重定向到 `/api/subjects/`（trailing slash）
- 重定向响应不包含 CORS 头
- 前端 Axios 请求的 URL 与后端路由定义不完全匹配

**解决方案：**
- 前端 API 请求统一使用带尾部斜杠的 URL（如 `/subjects/`）
- 或在后端设置 `redirect_slashes=False`（但可能引发其他问题）

---

### 3. API 参数校验失败 (422 错误)

**现象：**
- 请求返回 422 Unprocessable Entity
- 错误发生在 `/tasks/with-details` 接口

**根本原因：**
- 后端定义 `page_size` 最大值为 200
- 前端请求 `page_size=500`
- 参数验证失败

**教训：**
```
前后端的参数约束必须协调一致
前端不应假设后端能接受任意值
```

---

### 4. 前端显示 Mock 数据而非真实数据

**现象：**
- 科目管理显示 6 个科目（Mock 数据）
- 底部统计显示 20 个科目（真实统计）

**根本原因：**
- API 请求失败时，前端会 fallback 到 Mock 数据
- 由于后端 500 错误，请求被视为失败
- 用户看到的是本地模拟数据

**教训：**
```
Mock 数据是开发辅助，不应在生产中依赖
应该更明显地提示用户当前使用的是 Mock 数据
```

---

### 5. 行政课程（原教学计划）年级显示"无数据"

**现象：**
- 年级下拉框显示"无数据"
- 班级数据存在但无法选择年级

**根本原因：**
- 班级数据中 `grade` 字段可能为空
- 早期数据没有正确设置年级信息
- 前端代码依赖 `grade` 字段进行筛选

**解决方案：**
- 添加从班级名称解析年级的容错逻辑（如 `IG3-1` → `G3`）
- 在后端 API 返回时自动填充缺失的字段

---

### 6. Vue 组件 prop 类型验证失败

**现象：**
- 控制台警告：`Invalid prop: custom validator check failed for prop "type"`
- ElTag 组件报错

**根本原因：**
- `getSubjectTagType()` 函数在某些情况下返回空字符串或 undefined
- Element Plus 的 ElTag 组件要求 `type` 必须是特定的枚举值

**解决方案：**
- 函数返回值使用有效的默认值（如 `'info'`）
- 添加 null/undefined 检查

## 二、问题分类与通用解决思路

### 数据库相关问题

| 问题类型 | 检查方法 | 解决思路 |
|---------|---------|---------|
| 字段不存在 | 查看后端错误日志 | 执行数据库迁移或手动添加字段 |
| 数据类型不匹配 | 比对 ORM 模型与表结构 | 修改模型或调整数据库 |
| 数据缺失 | 检查必填字段 | 添加默认值或容错处理 |

### API 相关问题

| 问题类型 | 检查方法 | 解决思路 |
|---------|---------|---------|
| CORS 错误 | 检查网络请求和后端日志 | 确认后端正常运行，检查 URL 格式 |
| 422 错误 | 查看请求参数 | 确保参数符合后端约束 |
| 500 错误 | 查看后端错误堆栈 | 修复后端代码 bug |
| 404 错误 | 检查 URL 路径 | 确认路由注册正确 |

### 前端相关问题

| 问题类型 | 检查方法 | 解决思路 |
|---------|---------|---------|
| 数据不显示 | 检查 console.log 输出 | 确认数据加载和渲染逻辑 |
| 组件报错 | 查看 Vue 警告 | 修复 prop 类型或值 |
| 显示 Mock 数据 | 检查网络请求状态 | 确认 API 正常返回 |

## 三、开发流程改进建议

### 1. 数据库变更管理

**推荐做法：**

```bash
# 使用 Alembic 进行数据库迁移管理
pip install alembic
alembic init alembic

# 每次修改模型后：
alembic revision --autogenerate -m "描述变更"
alembic upgrade head
```

**检查清单：**
- [ ] 修改 ORM 模型前，先规划数据库变更
- [ ] 使用迁移工具而非手动修改数据库
- [ ] 在开发环境测试迁移后再应用到生产环境
- [ ] 保留迁移历史，便于回滚

### 2. 前后端协作规范

**API 契约先行：**

```yaml
# 先定义 API 规范，再分别实现
GET /api/v1/subjects/
  参数:
    - page: int, 默认 1
    - page_size: int, 范围 1-100, 默认 20
  响应:
    - code: 200
    - data.items: Subject[]
    - data.total: int
```

**参数约束同步：**
- 后端定义的参数范围应该记录在 API 文档中
- 前端请求时应遵守这些约束
- 使用 TypeScript 类型定义保持一致性

### 3. 错误处理策略

**后端：**
```python
# 使用全局异常处理器
@app.exception_handler(Exception)
async def global_exception_handler(request, exc):
    # 记录详细日志
    logger.error(f"Unhandled error: {exc}", exc_info=True)
    # 返回友好的错误信息（不暴露内部细节）
    return JSONResponse(
        status_code=500,
        content={"code": 500, "message": "服务器内部错误"}
    )
```

**前端：**
```javascript
// API 调用时区分错误类型
try {
  const res = await getSubjects()
} catch (error) {
  if (error.response?.status === 500) {
    // 后端错误 - 提示用户稍后重试
    ElMessage.error('服务器错误，请稍后重试')
  } else if (error.message === 'Network Error') {
    // 网络错误 - 检查后端是否运行
    ElMessage.warning('网络连接失败，请检查网络')
  }
  // 不要静默使用 Mock 数据，要明确提示
}
```

### 4. 开发环境检查清单

**每次开发前检查：**
- [ ] 后端服务是否正常运行
- [ ] 数据库连接是否正常
- [ ] 数据库表结构是否与代码同步
- [ ] 前端开发服务器是否正常

**添加新功能前：**
- [ ] 是否需要修改数据库？
- [ ] 是否需要新的 API 端点？
- [ ] 前后端参数约定是否明确？
- [ ] 是否需要处理旧数据兼容？

## 四、调试技巧总结

### 1. 快速定位问题来源

```
前端报错 → 检查浏览器 Network 面板
         ↓
      请求是否发出？
         ↓
    是 → 检查响应状态码
         ↓
      4xx/5xx → 检查后端日志
         ↓
      后端报错 → 查看错误堆栈定位问题
```

### 2. CORS 错误的真正原因

```
CORS 错误往往不是 CORS 配置问题！
常见真实原因：
1. 后端服务崩溃（500 错误没有 CORS 头）
2. URL 重定向（307 响应没有 CORS 头）
3. 后端服务未启动（无响应）

正确做法：先检查后端日志，再看 CORS 配置
```

### 3. 数据不显示的排查步骤

```javascript
// 1. 确认 API 返回数据
console.log('API 响应:', res)

// 2. 确认数据解析正确
console.log('解析后数据:', items)

// 3. 确认渲染数据正确
console.log('显示数据:', displayData.value)

// 4. 检查模板绑定
// v-for="item in displayData" - displayData 名称是否正确？
```

## 六、本次问题的核心教训

### 最重要的三点：

1. **代码与数据库必须同步**
   - 修改 ORM 模型后，立即更新数据库
   - 使用迁移工具管理变更

2. **查看后端日志是第一步**
   - CORS 错误往往只是表象
   - 真正的错误信息在后端日志中

3. **前后端契约要明确**
   - 参数范围、数据格式提前约定
   - 不要在前端假设后端能接受任意值
