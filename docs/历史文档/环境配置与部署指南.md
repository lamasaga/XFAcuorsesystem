## 二、日常开发操作

### 2.1 每次开发前的启动步骤

**⚠️ 重要：前端操作数据时，必须先启动后端服务！**

#### 步骤 1：启动后端服务

```bash
# 打开终端，进入后端目录
cd 排课系统/backend

# 启动后端服务
python -m uvicorn app.main:app --reload
```

启动成功标志：
```
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Started reloader process
```

验证方式：访问 http://localhost:8000/docs 可以看到 API 文档

#### 步骤 2：启动前端服务

```bash
# 打开新终端，进入前端目录
cd 排课系统/frontend

# 启动前端服务
npm run dev
```

启动成功标志：
```
VITE v5.x.x  ready in xxx ms

➜  Local:   http://localhost:5173/
```

访问 http://localhost:5173 或 http://localhost:3000（取决于 Vite 配置）

### 2.2 开发顺序建议

```
1. 先启动后端 → 2. 再启动前端 → 3. 开始开发/测试
```

### 2.3 关闭服务

在各自的终端按 `Ctrl + C` 即可停止服务。

## 三、前后端对接原理

### 3.1 架构图

```
┌─────────────────────────────────────────────────────────────┐
│                         用户浏览器                           │
│                    http://localhost:5173                    │
└─────────────────────────┬───────────────────────────────────┘
                          │ 用户操作
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    前端 (Vue 3 + Vite)                       │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐         │
│  │  页面组件    │  │  API 封装   │  │  状态管理   │         │
│  │  (.vue)     │→ │  (axios)    │→ │  (Pinia)   │         │
│  └─────────────┘  └──────┬──────┘  └─────────────┘         │
└──────────────────────────┼──────────────────────────────────┘
                           │ HTTP 请求 (REST API)
                           │ http://localhost:8000/api/v1/xxx
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                   后端 (FastAPI + Python)                    │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐         │
│  │   路由层    │→ │   服务层    │→ │   数据层    │         │
│  │  (router)   │  │  (service)  │  │   (crud)    │         │
│  └─────────────┘  └─────────────┘  └──────┬──────┘         │
└──────────────────────────────────────────┼──────────────────┘
                                           │ SQL 查询
                                           ▼
┌─────────────────────────────────────────────────────────────┐
│                    PostgreSQL 数据库                         │
│                    localhost:5432                           │
│                    数据库名: schedule_db                     │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 数据流示例（以添加教师为例）

```
1. 用户在前端填写表单，点击"保存"
   ↓
2. 前端调用 API：createTeacher(data)
   ↓
3. axios 发送 POST 请求到 http://localhost:8000/api/v1/teachers
   ↓
4. 后端 FastAPI 接收请求，路由到 teachers/router.py
   ↓
5. 调用 crud.py 中的 create_teacher() 函数
   ↓
6. SQLAlchemy 生成 INSERT SQL 语句，写入 PostgreSQL
   ↓
7. 数据库返回新创建的记录
   ↓
8. 后端返回 JSON 响应：{ code: 200, data: {...} }
   ↓
9. 前端接收响应，更新页面显示
```

### 3.3 关键文件对照表

| 功能 | 前端文件 | 后端文件 |
|------|---------|---------|
| API 基础配置 | `frontend/src/api/index.js` | `backend/app/core/config.py` |
| 教师管理 | `frontend/src/api/teachers.js` | `backend/app/modules/teachers/` |
| 班级管理 | `frontend/src/api/classes.js` | `backend/app/modules/classes/` |
| 科目管理 | `frontend/src/api/subjects.js` | `backend/app/modules/subjects/` |

### 3.4 字段命名转换

后端使用 **snake_case**（下划线），前端使用 **camelCase**（驼峰）：

| 后端字段 | 前端字段 |
|---------|---------|
| `weekly_hours` | `weeklyHours` |
| `max_weekly_hours` | `maxWeeklyHours` |
| `class_no` | `classNo` |
| `is_main` | `isMain` |

转换通常在前端 API 调用后进行：

```javascript
// 前端接收数据后转换
teachers.value = res.data.items.map(t => ({
  ...t,
  weeklyHours: t.weekly_hours,
  maxWeeklyHours: t.max_weekly_hours
}))
```

## 四、项目迁移指南

### 4.1 迁移前的准备（在原电脑上）

#### 1. 导出数据库

```bash
# 在 PostgreSQL 安装目录的 bin 文件夹中打开命令行
# 或者使用 pgAdmin 的备份功能

pg_dump -U postgres -d schedule_db -F c -f schedule_db_backup.dump
```

#### 2. 打包项目文件

需要复制的文件夹：
```
排课系统/
├── backend/          # 后端代码（必须）
├── frontend/         # 前端代码（必须）
├── docs/             # 文档（建议）
├── .cursorrules      # AI 规则（可选）
└── *.md              # 说明文档（建议）
```

**不需要复制的文件夹**（会自动生成）：
```
frontend/node_modules/     # 前端依赖（npm install 会重新生成）
backend/__pycache__/       # Python 缓存
backend/app/**/__pycache__/
```

### 4.2 新电脑上的安装步骤

#### 步骤 1：安装必要软件

| 软件 | 下载地址 | 备注 |
|------|---------|------|
| Python 3.11+ | https://www.python.org/downloads/ | 勾选 "Add to PATH" |
| Node.js 18+ | https://nodejs.org/ | 选择 LTS 版本 |
| PostgreSQL 15+ | https://www.postgresql.org/download/ | 记住设置的密码 |
| Git（可选） | https://git-scm.com/ | 版本控制 |

#### 步骤 2：配置 PostgreSQL

1. 安装完成后，打开 **pgAdmin 4**
2. 创建数据库 `schedule_db`
3. 如果有备份文件，恢复数据：
   ```bash
   pg_restore -U postgres -d schedule_db schedule_db_backup.dump
   ```

#### 步骤 3：配置后端

```bash
# 进入后端目录
cd 排课系统/backend

# 修改 .env 文件中的数据库密码
# DB_PASSWORD=你的PostgreSQL密码

# 安装 Python 依赖
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 如果没有恢复数据库备份，需要初始化数据库
python init_data.py
```

#### 步骤 4：配置前端

```bash
# 进入前端目录
cd 排课系统/frontend

# 安装依赖
npm install

# 如果网络慢，使用淘宝镜像
npm install --registry=https://registry.npmmirror.com
```

#### 步骤 5：验证安装

```bash
# 终端 1：启动后端
cd backend
python -m uvicorn app.main:app --reload

# 终端 2：启动前端
cd frontend
npm run dev
```

访问 http://localhost:5173 验证前端
访问 http://localhost:8000/docs 验证后端 API

### 4.3 迁移检查清单

- [ ] PostgreSQL 已安装并能登录
- [ ] 数据库 `schedule_db` 已创建
- [ ] `.env` 文件中的密码已修改为新电脑的密码
- [ ] 后端依赖已安装（`pip install -r requirements.txt`）
- [ ] 前端依赖已安装（`npm install`）
- [ ] 后端能正常启动（访问 /docs 有响应）
- [ ] 前端能正常启动（页面能打开）
- [ ] 前端能从后端获取数据（教师列表能显示）

## 五、常见问题排查

### 5.1 后端问题

| 问题 | 可能原因 | 解决方法 |
|------|---------|---------|
| `ModuleNotFoundError` | 依赖未安装 | `pip install -r requirements.txt` |
| `connection refused` | PostgreSQL 未启动 | 启动 PostgreSQL 服务 |
| `password authentication failed` | 密码错误 | 检查 `.env` 中的 `DB_PASSWORD` |
| `database "schedule_db" does not exist` | 数据库未创建 | 在 pgAdmin 中创建数据库 |
| `uvicorn` 命令不识别 | 未加入 PATH | 使用 `python -m uvicorn` |

### 5.2 前端问题

| 问题 | 可能原因 | 解决方法 |
|------|---------|---------|
| `Cannot find module 'xxx'` | 依赖未安装 | `npm install` |
| `Failed to resolve import "axios"` | axios 未安装 | `npm install axios` |
| `Network Error` | 后端未启动 | 先启动后端服务 |
| 页面显示 Mock 数据 | 后端未启动 | 启动后端，刷新页面 |
| 图标显示为红叉 | 组件引用问题 | 检查图标导入方式 |

### 5.3 数据库问题

| 问题 | 解决方法 |
|------|---------|
| 忘记 PostgreSQL 密码 | 重装 PostgreSQL 或修改 pg_hba.conf |
| 表不存在 | 运行 `python init_data.py` |
| 数据丢失 | 从备份恢复或重新初始化 |
