# 排课系统真实数据测试指南

> 本指南用于指导如何使用真实数据对排课引擎进行全流程测试。

---

## 一、 测试前准备

### 1.1 确认服务运行
确保后端和前端服务都已启动：
```bash
# 终端 1
image.png

# 终端 2
npm run dev
```

### 1.2 数据清理（可选）
为了获得干净的测试环境，建议重置数据库（**警告：会清空所有数据！**）：
```sql
DROP SCHEMA public CASCADE;
CREATE SCHEMA public;
```
然后重新运行初始化：
```bash
python init_data.py
```

---

## 二、 录入基础数据

请按照以下顺序在前端录入数据：

### 2.1 录入教师
*   访问 **数据管理 > 教师管理**
*   点击 "添加教师"
*   录入至少 5 名教师（语数英各 1 名，体育美术各 1 名）
*   **注意**：设置好他们的"周最大课时"（建议 20 节）。

### 2.2 录入班级
*   访问 **数据管理 > 班级管理**
*   系统已预置 31 个班级，确认它们都在。

### 2.3 录入科目
*   访问 **数据管理 > 科目管理**
*   确保 语文、数学、英语、体育、美术 已存在。

### 2.4 配置场地（关键）
*   访问 **数据管理 > 场地资源**
*   添加一个 "体育场"，容量 4，关联科目 "体育"。
*   添加一个 "美术教室"，容量 2，关联科目 "美术"。

### 2.5 配置分层课程（关键）
*   访问 **数据管理 > 分层课程**
*   添加一个 **G6 英语分层**：
    *   科目：英语
    *   年级：G6
    *   分层数：2
    *   周课时：5
    *   任课教师：为每个层级选择一位教师
*   保存后，系统会自动为每个层级创建对应的教学任务。
*   这意味着 G6 的所有班级英语课将在同一时间上，需要 2 位英语老师。

## 三、 生成教学任务

> **说明**：分层课程保存时会自动生成对应的教学任务。
> 行政课程需要在"数据管理 > 行政课程"页面手动配置。

为了测试，你需要**手动**往数据库插入一些任务，或者等待下一阶段开发"任务生成器"。

**临时方案：使用 API 文档手动创建任务**
1.  访问 http://localhost:8000/docs
2.  找到 `POST /api/v1/tasks/`
3.  创建几个任务：
    ```json
    {
      "teacher_id": 1,
      "class_id": 1,
      "subject_id": 1,
      "weekly_hours": 5
    }
    ```
    (你需要先去数据库查一下 teacher_id, class_id, subject_id 是多少)

---

## 四、 执行排课

1.  访问 **自动排课** 页面。
2.  点击 **下一步** -> **开始排课**。
3.  观察控制台（后端终端）的输出日志：
    *   `>>> 开始分层课排课`
    *   `>>> 开始场地课排课`
    *   `>>> 开始普通课排课`
4.  如果看到 `✅ 排课完成`，说明引擎运行成功！

---

## 五、 常见问题

*   **Q: 排课失败，提示无法找到时间槽？**
    *   A: 可能是资源冲突。检查是否所有老师都在该时间段忙碌，或者场地容量已满。
*   **Q: 分层课没排进去？**
    *   A: 检查 `TeachingTask` 表中，这些任务的 `layer_group_id` 是否正确设置。目前需要手动关联（或者等待任务生成器开发）。
