在数学中，你研究群、环、域，研究的是结构和保持结构的操作（同态/同构）。
在算法中，我们研究的是数据结构（数据的形态）和算法（数据的变换）。
算法，本质上就是“构造性证明”（Constructive Proof）。
数学家证明“方程有解（Existence）”，程序员证明“我能用有限的步骤把解找出来（Construction）”。

一、 贪心算法 (Greedy Algorithm)
——“活在当下，只选眼前最好的”
1. 核心概念
每一步都做出在当前看来最好的选择，期望通过局部最优达到全局最优。
优点：速度极快，实现简单。
缺点：短视，通常得不到完美解（Global Optimum），只能得到近似解。
2. 我们的项目案例
你刚刚看到的 NormalScheduler 和 SlotFinder 就是典型的贪心算法。
场景：给张老师安排一节数学课。
逻辑：
扫描周一第1节：有空吗？有。好，就占这个坑！
不再考虑周一第2节会不会更好，也不考虑如果占了第1节，会不会导致李老师没法排课。
代码映射：
    # 贪心逻辑：找到第一个 available 的就 return，不再继续找    if available_slots:        return available_slots[0] 
3. 数学/代数直觉
想象你在一个偏序集（Poset）中。贪心算法就像是沿着单调递增的路径一直走，直到走不动为止。它不回头，也不眺望远方。
二、 回溯算法 (Backtracking)
——“不撞南墙不回头，撞了南墙换条路”
1. 核心概念
这是解决约束满足问题（CSP）的通用解法。它构建一棵“状态树”，深度优先地去搜索。如果发现当前路径走不通（违反约束），就回溯（Backtrack）到上一个节点，换一个选择。
2. 我们的项目案例
我们的 LayerScheduler（分层排课）目前是贪心的，但为了保证成功率，未来必须升级为回溯算法。
场景：G6 英语分层，有 A, B, C, D 四个班，必须同时上课。
贪心做法：
给 A 班找到周一第1节。
给 B 班找周一第1节... 哎呀，B班老师这节课没空！
结果：排课失败，报错。
回溯做法：
尝试周一第1节... B班老师没空。-> 回溯！撤销 A 班的安排。
尝试周一第2节... 大家都有空！-> 成功。
3. 数学/代数直觉
这就好比在群（Group）的Cayley图（凯莱图）上走迷宫。你尝试各种生成元的组合，如果走到死胡同，就退回来乘以逆元（Inverse Element），回到上一个状态。
三、 图论算法 (Graph Algorithms)
——“排课问题的本质是图着色”
1. 核心概念
排课问题在数学上等价于 图着色问题（Graph Coloring Problem）。这是一个经典的 NP-Complete 问题。
节点 (Vertex)：每一节要上的课（例如：张老师-G1班-数学）。
边 (Edge)：冲突关系。如果两节课由同一个老师上，或者属于同一个班级，它们之间就有一条连线。
颜色 (Color)：时间槽（周一第1节是红色，周一第2节是蓝色...）。
目标：给所有节点涂色，使得相连的节点颜色不同（即：有冲突的课不能排在同一时间）。
2. 我们的项目案例
ScheduleState：本质上是在维护这个图的邻接矩阵。
Hard Constraints：定义了哪些节点之间必须有连线。
3. 数学/代数直觉
这是拓扑学和组合数学的领域。如果你对同构（Isomorphism）感兴趣，你会发现很多看似风马牛不相及的问题（如地图着色、数独、排课），其背后的代数结构（图的结构）是完全同构的。
四、 启发式算法 (Heuristic / Meta-heuristic)
——“上帝掷骰子，模拟自然界的智慧”
1. 核心概念
当问题规模太大（比如几千节课），回溯算法算几百年都算不完时，我们就不追求“完美解”了，而是追求“足够好的解”。我们模仿自然界的物理或生物过程。
模拟退火 (Simulated Annealing)：模仿金属冷却结晶的过程。先允许随意的混乱（高温），然后慢慢降低容忍度（降温），最终稳定在一个低能态（冲突少的课表）。
遗传算法 (Genetic Algorithm)：模仿生物进化。生成 100 个随机课表（种群），让它们“杂交”、“变异”，淘汰掉差的，保留好的。
2. 我们的项目案例
这是我们 Phase 4 要做的全局优化。
场景：课排出来了，但是张老师上午有课，下午有课，中间空了3小时（空窗期），很不爽。
做法：随机交换张老师的两节课，看看“不爽程度”有没有降低。如果降低了，就保留这次交换。
3. 数学/代数直觉
这涉及概率论和统计力学。我们在一个巨大的、崎岖不平的解空间曲面上，寻找全局最小点。
五、 分治法 (Divide and Conquer)
——“大事化小，各个击破”
1. 核心概念
将一个复杂问题分解成两个或多个相同或相似的子问题，直到子问题可以简单地直接求解，原问题的解即子问题解的合并。
2. 我们的项目案例
这就是我们整个 Phase 2 的架构设计：
我们没有试图写一个 SuperAlgorithm 一次性排完所有课。
我们将问题分解为：
LayerScheduler（先排最难的）
VenueScheduler（再排受限的）
NormalScheduler（最后排容易的）
这种分治策略极大地降低了算法的复杂度。
