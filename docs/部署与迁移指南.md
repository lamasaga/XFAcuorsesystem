## 一、方案总览与选型建议

| 方案 | 适用场景 | 难度 | 优点 | 缺点 |
|------|---------|------|------|------|
| **A. Docker 容器化** | 标准化交付、多环境部署 | ⭐⭐ | 环境一致、可复制、维护简单 | 需要安装 Docker |
| **B. 云服务器 Web 应用** | 多人远程访问、长期使用 | ⭐⭐⭐ | 随时随地访问、多人协作 | 需要持续付费服务器 |
| **C. 桌面应用打包** | 单机离线使用、分发给非技术人员 | ⭐⭐⭐⭐ | 双击即用、无需网络 | 安装包大、更新不便 |
| **D. 局域网部署包** | 校园内网使用 | ⭐⭐ | 无需外网、速度快 | 只能局域网访问 |
| **E. Docker Compose 交付** | 给有技术能力的人交付 | ⭐ | 一条命令启动、最简洁 | 对方需懂 Docker |

### 推荐选择

- **如果给学校 IT 部门使用** → 方案 A 或 E（Docker 方式最省心）
- **如果要公网访问、多校区共用** → 方案 B（云服务器）
- **如果要给非技术人员一个"程序"** → 方案 C（桌面应用）
- **如果只在校园内网用** → 方案 D（局域网部署包）

## 二、方案 A：Docker 容器化部署（推荐）

### 2.1 原理

将前端、后端、数据库分别打包为 Docker 镜像，通过 Docker Compose 编排，一条命令启动所有服务。

### 2.2 准备工作

#### 创建后端 Dockerfile

在 `backend/` 目录下创建 `Dockerfile`：

```dockerfile
# backend/Dockerfile
FROM python:3.10-slim

WORKDIR /app

# 安装系统依赖
RUN apt-get update && apt-get install -y \
    libpq-dev gcc \
    && rm -rf /var/lib/apt/lists/*

# 复制依赖文件并安装
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 复制源码
COPY . .

# 暴露端口
EXPOSE 8000

# 启动命令
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

#### 创建前端 Dockerfile

在 `frontend/` 目录下创建 `Dockerfile`：

```dockerfile
# frontend/Dockerfile

# 构建阶段
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# 运行阶段
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

#### 创建 Nginx 配置

在 `frontend/` 目录下创建 `nginx.conf`：

```nginx
server {
    listen 80;
    server_name localhost;

    root /usr/share/nginx/html;
    index index.html;

    # 前端路由 - 所有路径都返回 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 代理
    location /api/ {
        proxy_pass http://backend:8000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 300s;  # 排课求解可能需要较长时间
    }
}
```

### 2.3 Docker Compose 编排

在项目根目录创建 `docker-compose.yml`：

```yaml
version: '3.8'

services:
  # PostgreSQL 数据库
  db:
    image: postgres:14-alpine
    restart: always
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: ${DB_PASSWORD:-your_secure_password}
      POSTGRES_DB: schedule_db
    volumes:
      - pgdata:/var/lib/postgresql/data
    ports:
      - "5432:5432"

  # 后端 API
  backend:
    build: ./backend
    restart: always
    depends_on:
      - db
    environment:
      DB_HOST: db
      DB_PORT: 5432
      DB_USER: postgres
      DB_PASSWORD: ${DB_PASSWORD:-your_secure_password}
      DB_NAME: schedule_db
      DEBUG: "false"
    ports:
      - "8000:8000"

  # 前端 (Nginx)
  frontend:
    build: ./frontend
    restart: always
    depends_on:
      - backend
    ports:
      - "80:80"

volumes:
  pgdata:
```

### 2.4 启动步骤

```bash
# 1. 克隆项目（或拷贝项目文件夹）
cd XfaCourseSchedulingSystem

# 2. 设置数据库密码（可选，不设则使用默认值）
export DB_PASSWORD=your_secure_password

# 3. 构建并启动所有服务
docker-compose up -d --build

# 4. 查看运行状态
docker-compose ps

# 5. 初始化数据库表（首次部署时）
docker-compose exec backend python -c "
from app.core.database import engine, Base
from app.modules.teachers.models import *
from app.modules.classes.models import *
from app.modules.subjects.models import *
from app.modules.tasks.models import *
from app.modules.layers.models import *
from app.modules.venues.models import *
from app.modules.schedules.models import *
Base.metadata.create_all(bind=engine)
print('数据库表创建完成')
"
```

访问 `http://localhost` 即可使用系统。

### 2.5 维护命令

```bash
# 停止服务
docker-compose down

# 查看日志
docker-compose logs -f backend

# 备份数据库
docker-compose exec db pg_dump -U postgres schedule_db > backup.sql

# 恢复数据库
cat backup.sql | docker-compose exec -T db psql -U postgres schedule_db

# 更新部署
git pull
docker-compose up -d --build
```

## 三、方案 B：云服务器部署为 Web 应用

### 3.1 选择云服务器

| 云服务商 | 推荐配置 | 参考价格 |
|---------|---------|---------|
| 阿里云 ECS | 2核4G、50G SSD | ~100-200 元/月 |
| 腾讯云 CVM | 2核4G、50G SSD | ~100-200 元/月 |
| 华为云 ECS | 2核4G、50G SSD | ~100-200 元/月 |
| AWS EC2 | t3.medium (2核4G) | ~$30-50/月 |

> **最低配置**：1核2G 也可以运行（排课求解较慢），推荐 2核4G 以获得良好体验。

### 3.2 服务器环境准备（以 Ubuntu 22.04 为例）

```bash
# 1. 更新系统
sudo apt update && sudo apt upgrade -y

# 2. 安装 Docker 和 Docker Compose
curl -fsSL https://get.docker.com | sh
sudo apt install -y docker-compose-plugin

# 3. 将当前用户加入 docker 组
sudo usermod -aG docker $USER
newgrp docker

# 4. 安装 Git（如需从仓库拉取）
sudo apt install -y git
```

### 3.3 使用 Docker 方式部署（推荐）

参照 [方案 A](#二方案-adocker-容器化部署推荐) 的步骤即可，在云服务器上执行相同的命令。

### 3.4 手动部署（不使用 Docker）

如果不使用 Docker，需要手动安装各组件：

```bash
# ---------- 1. 安装 PostgreSQL ----------
sudo apt install -y postgresql postgresql-contrib
sudo -u postgres psql -c "CREATE DATABASE schedule_db;"
sudo -u postgres psql -c "ALTER USER postgres PASSWORD 'your_password';"

# ---------- 2. 安装 Python 环境 ----------
sudo apt install -y python3.10 python3.10-venv python3-pip
cd /opt/schedule-system/backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# ---------- 3. 安装 Node.js 并构建前端 ----------
curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
sudo apt install -y nodejs
cd /opt/schedule-system/frontend
npm ci
npm run build

# ---------- 4. 安装 Nginx ----------
sudo apt install -y nginx
```

#### 配置后端 systemd 服务

创建 `/etc/systemd/system/schedule-backend.service`：

```ini
[Unit]
Description=Schedule System Backend
After=postgresql.service

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/schedule-system/backend
Environment="PATH=/opt/schedule-system/backend/.venv/bin"
ExecStart=/opt/schedule-system/backend/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable schedule-backend
sudo systemctl start schedule-backend
```

#### 配置 Nginx

编辑 `/etc/nginx/sites-available/schedule`：

```nginx
server {
    listen 80;
    server_name your-domain.com;  # 替换为你的域名或 IP

    # 前端静态文件
    root /opt/schedule-system/frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 代理
    location /api/ {
        proxy_pass http://127.0.0.1:8000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 300s;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/schedule /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx
```

### 3.5 配置 HTTPS（可选但推荐）

使用 Let's Encrypt 免费 SSL 证书：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

### 3.6 配置防火墙

```bash
sudo ufw allow 22/tcp    # SSH
sudo ufw allow 80/tcp    # HTTP
sudo ufw allow 443/tcp   # HTTPS
sudo ufw enable
```

### 3.7 同机多项目部署（与现有服务共存）

> 当服务器上已运行其他项目（如 `Alevelinfo` 的 Node/Express 服务），需要避免端口、目录、环境冲突。

#### 关键约束

| 项 | 现有项目 | 排课系统 | 规则 |
|----|---------|---------|------|
| 端口 | `127.0.0.1:3001` | `127.0.0.1:8001` | 互不占用 |
| 对外暴露 | Nginx `80/443` | Nginx `80/443` | 通过域名/路径分流 |
| 目录 | `/opt/alevelinfo/` | `/opt/schedule/` | 严格隔离 |
| Python 环境 | 系统 Python | 独立 `venv` | 禁止全局安装 |
| 数据库 | SQLite / 其他 | PostgreSQL / SQLite | 互不混用 |

#### 服务器目录约定

```text
/opt/
  alevelinfo/                 # 现有项目（不动）
  schedule/                   # 排课系统（新增）
    ├─ repo/                  # 源码目录
    ├─ .env                   # 环境变量（只在服务器）
    ├─ .venv/                 # Python 虚拟环境
    ├─ frontend-dist/         # 前端构建产物
    ├─ log/                   # 应用日志
    └─ backup/                # 数据备份
```

#### Nginx 同机分流配置

**推荐方式：子域名分流**（需要域名解析）

```nginx
# schedule.example.com → 排课系统
server {
    listen 80;
    server_name schedule.example.com;

    root /opt/schedule/frontend-dist;
    index index.html;

    location /api/v1/ {
        proxy_pass http://127.0.0.1:8001/api/v1/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}

# alevel.example.com → 现有项目（保持不变）
server {
    listen 80;
    server_name alevel.example.com;
    # ... 现有配置
}
```

**无域名方式：端口分流**

```nginx
server {
    listen 8080;  # 对外新开端口
    server_name _;

    root /opt/schedule/frontend-dist;
    index index.html;

    location /api/v1/ {
        proxy_pass http://127.0.0.1:8001/api/v1/;
        proxy_read_timeout 300s;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

> ⚠️ **安全规则**：`8001` 仅监听 `127.0.0.1`，不暴露在公网安全组。公网只放行 `22/80/443`（或额外放行 `8080`）。

#### 后端 systemd 服务模板

创建 `/etc/systemd/system/schedule.service`：

```ini
[Unit]
Description=Xfa Course Scheduling - FastAPI
After=network.target

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/opt/schedule/repo/backend
EnvironmentFile=-/opt/schedule/repo/backend/.env
ExecStart=/opt/schedule/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8001
Restart=always
RestartSec=3

NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now schedule
sudo systemctl status schedule --no-pager -l
```

#### 发布更新流程

```bash
# 后端更新
cd /opt/schedule/repo
git pull
source /opt/schedule/.venv/bin/activate
pip install -r backend/requirements.txt
sudo systemctl restart schedule

# 前端更新
cd /opt/schedule/repo/frontend
npm ci
VITE_API_BASE=/api/v1 npm run build
sudo rsync -a --delete dist/ /opt/schedule/frontend-dist/
sudo nginx -t && sudo systemctl reload nginx
```

#### 部署前自检清单

- [ ] `3001`（现有）不改，`8001`（新增）仅监听 `127.0.0.1`
- [ ] 安全组只放行 `22/80/443`（或额外 `8080`）
- [ ] `schedule` systemd 服务状态 `active (running)`
- [ ] Nginx `nginx -t` 通过
- [ ] `backend/.env` 不在 Git 仓库中
- [ ] PostgreSQL 备份策略已就绪

## 四、方案 C：打包为桌面应用程序（已实现）

> 本方案已在项目中完整实现，可以直接使用一键构建脚本。

### 4.1 架构设计

```
┌─────────────────────────────────────────────┐
│             Electron 桌面壳                  │
│  ┌─────────────────────────────────────────┐ │
│  │     前端 (Vue 3 构建产物)               │ │
│  │     file:///...frontend/index.html      │ │
│  └───────────────┬─────────────────────────┘ │
│                  │ HTTP API                   │
│  ┌───────────────▼─────────────────────────┐ │
│  │     后端 (PyInstaller 打包)             │ │
│  │     FastAPI + OR-Tools + SQLite         │ │
│  │     → run_desktop.exe                   │ │
│  └───────────────┬─────────────────────────┘ │
│                  │                            │
│  ┌───────────────▼─────────────────────────┐ │
│  │     SQLite 数据库                       │ │
│  │     → data/schedule.db（自动创建）      │ │
│  └─────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

**关键设计决策：**

| 决策 | 选择 | 原因 |
|------|------|------|
| 数据库 | **SQLite**（非 PostgreSQL） | 免安装，零配置，数据库文件随应用走 |
| 后端打包 | PyInstaller --onedir | 包含 Python 运行时 + OR-Tools |
| 前端打包 | Vite build → 静态 HTML | 相对路径 `base: './'` |
| 桌面壳 | Electron + electron-builder | 生成 .exe 安装包 |

### 4.2 文件结构

项目中已创建以下文件：

```
项目根目录/
├── electron-app/              # Electron 包装项目
│   ├── package.json           # Electron 依赖和构建配置
│   ├── main.js                # 主进程（启动后端、加载前端）
│   ├── preload.js             # 预加载脚本
│   └── loading.html           # 启动加载画面
│
├── backend/
│   ├── run_desktop.py         # 桌面模式启动脚本（SQLite）
│   └── app/core/
│       ├── config.py          # 已支持 USE_SQLITE 环境变量
│       ├── database.py        # 已支持 SQLite 连接
│       └── compat.py          # 数据库兼容层（ARRAY→JSON）
│
├── build-desktop.bat          # Windows 一键构建脚本
└── dist-electron/             # 构建输出（安装包在此）
```

### 4.3 一键构建（推荐）

在项目根目录双击 `build-desktop.bat`，脚本会自动完成全部 4 步：

```
步骤 1: npm run build        → 构建前端静态文件
步骤 2: pyinstaller           → 打包后端为 .exe
步骤 3: npm install (electron) → 安装 Electron 依赖
步骤 4: electron-builder      → 生成 .exe 安装包
```

构建完成后，安装包在 `dist-electron/` 文件夹中。

### 4.4 手动构建步骤

如果一键脚本出错，可以手动分步执行：

**步骤 1：构建前端**

```bash
cd frontend
npm install
npm run build
```

**步骤 2：打包后端**

```bash
cd backend
pip install pyinstaller

pyinstaller --noconfirm --clean ^
    --name run_desktop ^
    --onedir ^
    --console ^
    --add-data "app;app" ^
    --hidden-import uvicorn.logging ^
    --hidden-import uvicorn.protocols.http ^
    --hidden-import uvicorn.protocols.http.auto ^
    --hidden-import uvicorn.protocols.http.h11_impl ^
    --hidden-import uvicorn.protocols.http.httptools_impl ^
    --hidden-import uvicorn.protocols.websockets ^
    --hidden-import uvicorn.protocols.websockets.auto ^
    --hidden-import ortools ^
    --hidden-import ortools.sat ^
    --hidden-import ortools.sat.python ^
    --hidden-import ortools.sat.python.cp_model ^
    --hidden-import sqlalchemy.dialects.sqlite ^
    --hidden-import pydantic ^
    --hidden-import pydantic_settings ^
    --hidden-import app.core.compat ^
    run_desktop.py
```

然后复制结果：

```bash
# 回到项目根目录
cd ..
xcopy /E /I backend\dist\run_desktop backend-dist
```

**步骤 3：打包 Electron 安装包**

```bash
cd electron-app
npm install
npm run build:win
```

### 4.5 另一台电脑安装使用

> **重点：使用 SQLite 模式打包后，另一台电脑不需要安装任何数据库！**

安装流程：

```
另一台电脑（用户端）
  │
  ├─ 1. 获取安装包
  │     拿到 dist-electron/ 文件夹中的 .exe 安装文件
  │
  ├─ 2. 双击安装
  │     运行安装程序，选择安装路径，完成安装
  │     → 无需安装 Python
  │     → 无需安装 Node.js
  │     → 无需安装 PostgreSQL（使用内嵌 SQLite）
  │
  ├─ 3. 双击桌面图标启动
  │     → Electron 自动启动后端（run_desktop.exe）
  │     → 后端自动创建 SQLite 数据库文件
  │     → 前端页面自动加载
  │
  └─ 4. 开始使用
        从 Dashboard 开始录入数据，进行排课
```

**数据库说明：**
- 数据库文件（`schedule.db`）在首次启动时**自动创建**
- 存放在应用安装目录的 `resources/backend/data/` 下
- 所有数据（教师、班级、课表等）都存在这个文件中
- 备份数据只需复制这个 `.db` 文件
- 迁移到新电脑只需复制安装目录或重新安装后替换 `.db` 文件

### 4.6 构建环境要求

构建机器（你的开发电脑）需要：

| 工具 | 版本要求 | 用途 |
|------|---------|------|
| Python | 3.10+ | 后端 + PyInstaller 打包 |
| Node.js | 18+ | 前端构建 + Electron 打包 |
| pip 包 | pyinstaller | 将 Python 打包为 .exe |
| npm 包 | electron, electron-builder | 生成桌面安装包 |

> 用户端电脑不需要上述任何工具，安装包已包含所有运行时。

### 4.7 安装包大小参考

| 组件 | 预估大小 |
|------|---------|
| Python 运行时 + OR-Tools | ~150 MB |
| FastAPI + SQLAlchemy | ~30 MB |

## 七、通用注意事项

### 7.1 数据库迁移

如果已有数据需要迁移到新环境：

```bash
# 在旧环境导出
pg_dump -U postgres -h localhost schedule_db > schedule_backup.sql

# 在新环境导入
psql -U postgres -h localhost schedule_db < schedule_backup.sql
```

### 7.2 前端 API 地址配置

生产环境中前端需要知道后端 API 的地址。推荐使用 Nginx 反向代理（前后端同域），这样前端可以使用相对路径 `/api/v1/...`，无需修改代码。

如果前后端分别部署在不同端口/域名，需要：

1. 后端启用 CORS：

```python
# backend/app/main.py 中添加
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],  # 生产环境应限制为具体域名
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

2. 前端配置 API 地址（修改 `frontend/src/api/index.js`）。

### 7.3 环境变量管理

不同部署环境使用不同的 `.env` 文件：

| 环境 | 文件 | DB_HOST | DEBUG |
|------|------|---------|-------|
| 本地开发 | `.env` | localhost | true |
| Docker | docker-compose 环境变量 | db | false |
| 云服务器 | `.env.production` | localhost / RDS地址 | false |

### 7.4 OR-Tools 兼容性

Google OR-Tools 是排课引擎的核心依赖，需要注意：

- **支持的平台**：Windows (x64)、Linux (x64)、macOS (x64/arm64)
- **Python 版本**：3.8 - 3.12
- **安装方式**：`pip install ortools`
- **包体积**：约 50-80 MB
- **注意**：ARM 架构的服务器（如某些云服务器）可能不支持，请优先选择 x86_64 架构

### 7.5 性能建议

| 部署方式 | 推荐配置 | 排课速度参考 |
|---------|---------|------------|
| 单机/桌面 | 4核8G | 28 班约 60-120 秒 |
| 云服务器 | 2核4G | 28 班约 120-180 秒 |
| Docker | 4核8G | 28 班约 60-120 秒 |

> 排课速度主要受 CPU 核数和求解器时间限制影响。OR-Tools CP-SAT 默认使用 4 个 worker 线程。

### 7.6 数据备份策略

建议配置定时备份：

```bash
# crontab 每天凌晨 2 点自动备份
0 2 * * * pg_dump -U postgres schedule_db | gzip > /backup/schedule_$(date +\%Y\%m\%d).sql.gz

# 保留最近 30 天的备份
0 3 * * * find /backup -name "schedule_*.sql.gz" -mtime +30 -delete
```

## 八、常见问题 FAQ

### Q1: Docker 部署后数据库连接失败？

**A:** 检查 `docker-compose.yml` 中后端的 `DB_HOST` 是否设为 `db`（Docker 服务名），而不是 `localhost`。

### Q2: 前端页面空白？

**A:** 可能原因：
1. 前端构建时 `base` 路径不对 → 在 `vite.config.js` 中设置 `base: '/'`
2. Nginx 配置缺少 `try_files` → SPA 路由需要回退到 `index.html`

### Q3: 打包为桌面应用后 OR-Tools 报错？

**A:** PyInstaller 可能未包含 OR-Tools 的动态库。在 `.spec` 文件中添加：

```python
# 在 Analysis 中添加
hiddenimports=['ortools.sat.python.cp_model', 'ortools.sat.pywraplp']
```

### Q4: 云服务器排课超时？

**A:** 
1. 增加 Nginx 的 `proxy_read_timeout`（至少 300 秒）
2. 在排课参数中降低优化等级（`optimization: 2` 或 `1`）
3. 升级服务器 CPU 配置

### Q5: 如何从 PostgreSQL 迁移到 SQLite？

**A:** 需要修改 `backend/app/core/database.py` 中的数据库连接字符串。SQLite 不支持部分 PostgreSQL 特性（如 `ARRAY` 类型），需要相应修改模型定义。推荐仅在桌面打包方案中使用 SQLite。

### Q6: 多个学校可以共用一套系统吗？

**A:** 当前系统为单租户设计。如需多学校共用，有两种方案：
1. **简单方案**：为每个学校部署独立实例（推荐）
2. **复杂方案**：改造为多租户架构（需要开发工作）
