## 一、项目概述

面向 K-12 双语/国际学校的智能排课系统。核心使用 **Google OR-Tools CP-SAT** 约束满足求解器，支持分层教学、早晚班、多场地等复杂约束。

### 当前规模

| 维度 | 数据 |
|------|------|
| 班级 | 28 个（国际班 I + 综素班 N） |
| 年级 | PK / KG / G1-G12 |
| 教师 | ~54 人 |
| 科目 | ~32 门 |
| 教学任务 | ~149 条 |
| 分层组 | ~19 组 |
| 场地 | 6 个特殊场地 |
| A-Level学生 | G10-G12 |
| 课程班 | 若干 |

### 技术栈

| 层 | 技术 | 版本 |
|----|------|------|
| 前端 | Vue 3 + Vite + Element Plus | Vue ^3.4.0 |
| 后端 | Python + FastAPI + SQLAlchemy | Python 3.10+ |
| 数据库 | PostgreSQL（生产）/ SQLite（桌面） | PG 14+ |
| 求解器 | Google OR-Tools CP-SAT | latest |
| 桌面端 | Electron + electron-builder | ^28.0.0 |

## 三、命名规范

### 3.1 跨层命名对照

| 层级 | 风格 | 示例 |
|------|------|------|
| 数据库字段 | `snake_case` | `max_weekly_hours`, `homeroom_cn_id` |
| 后端 Python | `snake_case` | `teacher_id`, `weekly_hours` |
| 后端 Pydantic | `snake_case` | `is_continuous`, `preferred_period` |
| 前端 JS 变量 | `camelCase` | `maxWeeklyHours`, `isContinuous` |
| 前端 API 请求 | `snake_case` | 请求体 key 与后端一致 |
| 前端组件内表单 | `camelCase` | `weeklyHours`, `homeroomCnId` |

> **约定**：前端在组件内部使用 `camelCase`，组装 API 请求时转换为 `snake_case` 的 key。

### 3.2 业务枚举值

| 概念 | 值 | 含义 |
|------|-----|------|
| 教师类型 | `"CN"` / `"EN"` | 中教 / 外教 |
| 学部 | `"PRIMARY"` / `"SECONDARY"` / `"BOTH"` | 小学部(PK-G5) / 中学部(G6-G12) / 贯通 |
| 班级类型 | `"I"` / `"N"` | 国际班 / 综素班 |
| 年级 | `"PK"`, `"KG"`, `"G1"`~`"G12"` | — |
| 科目分类 | `"文化课"` / `"艺术"` / `"体育"` / `"综合"` | — |
| 教师标签 | `"HOMEROOM_TEACHER"`, `"ASSISTANT_HOMEROOM"`, `"PRIMARY_ADMIN"`, `"SECONDARY_ADMIN"` | — |
| 优先时段 | `"MORNING"` / `"AFTERNOON"` | 上午优先 / 下午优先 |
| 分层类型 | `"LAYER"` / `"COMBINE"` | 分层 / 合班 |
| 班次 | `"morning"` / `"evening"` | 早班(全天) / 晚班(上午不可用) |
| 学生状态 | `"ACTIVE"` / `"INACTIVE"` / `"GRADUATED"` | 在读 / 休学 / 毕业 |

## 七、排课引擎速览

### 7.1 执行流程

```
ScheduleEngine.run()
  ├─ 1. 清理旧方案 (保留最近6批)
  ├─ 2. 从 DB 加载所有数据
  ├─ 3. 读取约束配置
  ├─ 4. CPScheduleSolver.solve()
  │      ├─ SessionBuilder.build()   → ScheduleSession 列表
  │      ├─ _create_variables()      → x[session][day,period] BoolVar
  │      ├─ _add_hard_constraints()  → H1-H4
  │      ├─ _apply_configurable_constraints() → R1-R9
  │      └─ _run_solver()            → OR-Tools CP-SAT
  └─ 5. 保存结果到 schedules/schedule_items
```

### 7.2 约束体系

| 层级 | 约束 | 说明 | 默认 |
|------|------|------|------|
| **物理硬约束** | H1: 每个session恰好1个槽位 | 不可关闭 | — |
| | H2: 教师无冲突 | 不可关闭 | — |
| | H3: 班级无冲突 | 不可关闭 | — |
| | H4: 场地容量上限 | 不可关闭 | — |
| **可配置约束** | R1: 每日同科目上限≤2 | Hard | weight 10 |
| | R2: 主科优先上午 | Soft | weight 8 |
| | R3: 科目均匀分布 | Soft | weight 6 |
| | R4: 艺体课避开第1节 | Soft | weight 5 |
| | R5: 场地分散使用 | Soft | weight 4 |
| | R6: 早晚班教师约束 | Soft | weight 3 |
| | R7: 会议/教研预留 | Soft | weight 2 |
| | R8: 教研组组会 | Hard | weight 10 |
| | R9: 管理干部会议 | Hard | weight 10 |

### 7.3 关键业务规则

- **连堂课**: `is_continuous=True` 时，每周恰好 1 次连堂(duration=2) + 剩余为单节
- **分层课**: 同分层组的所有层级必须在**完全相同的时间槽**（原子操作）
- **方案管理**: 每次排课生成一个 `batch_id`，自动保留最近 6 批，已激活方案永不清理
- **求解失败诊断**: INFEASIBLE 时逐层放松约束（H1→H1+H2→...），定位冲突源

### 8.4 新增功能 checklist

修改任何概念（字段、枚举、规则）时，沿完整链路检查：

```
□ 数据库表 / ORM 模型 (modules/xxx/models.py)
□ Pydantic Schema (modules/xxx/schemas.py)
□ 后端 CRUD (modules/xxx/crud.py)
□ 后端路由 (modules/xxx/router.py)
□ 前端 API 调用层 (src/api/xxx.js)
□ 前端页面显示逻辑 (src/views/...)
□ 前端表单/筛选/下拉选项
□ 排课引擎（如影响约束或数据模型）
□ 导入模板字段（如使用 BaseImporter）
□ 初始化数据 / Mock 数据
```

### 8.5 调试原则

**先看后端日志——80%的前端问题根源在后端。**

```
前端报错
  → 检查浏览器 Network 面板（请求是否发出？状态码？）
    → 4xx/5xx → 立即检查后端日志和错误堆栈
    → 200 但数据异常 → 检查后端返回的原始数据结构
    → 请求未发出 → 检查前端代码逻辑
```
