# 排课系统数据流分析

## 概述

本文档详细分析了排课系统的数据模型、引擎架构和完整的数据流程，从 API 调用到求解器执行再到结果存储。

---

## 1. 数据库模型（存储排课结果）

### 1.1 Schedule（排课方案主表）

**位置**: `backend/app/modules/schedules/models.py`

```python
class Schedule(Base):
    """排课方案主表"""
    __tablename__ = "schedules"
    id = Column(Integer, primary_key=True, index=True)
    name = Column(String, default="未命名课表")
    is_active = Column(Boolean, default=False)
```

**说明**:
- 每个排课方案对应一个 `Schedule` 记录
- `is_active` 标记当前使用的课表（同一时间只能有一个激活）
- 支持存储多个方案，通过 `is_active` 区分

### 1.2 ScheduleItem（课表项）

**位置**: `backend/app/modules/schedules/models.py`

```python
class ScheduleItem(Base):
    """课表项 - 记录某节课的具体安排"""
    __tablename__ = "schedule_items"
    
    id = Column(Integer, primary_key=True, index=True)
    schedule_id = Column(Integer, ForeignKey("schedules.id"))
    
    task_id = Column(Integer, ForeignKey("teaching_tasks.id"))
    day = Column(Integer, nullable=False)  # 1-5 (周一到周五)
    period = Column(Integer, nullable=False)  # 1-9 (第几节)
    
    # 冗余字段方便查询
    teacher_id = Column(Integer, nullable=True)
    class_id = Column(Integer, nullable=True)
    subject_id = Column(Integer, nullable=True)
    
    # 唯一约束：同一个班级同一时间只能上一节课
    __table_args__ = (
        UniqueConstraint('schedule_id', 'class_id', 'day', 'period', 
                        name='uq_schedule_class_time'),
    )
```

**说明**:
- 每个 `ScheduleItem` 代表一节课的具体安排（某班级在某天某节上某科目）
- 通过 `schedule_id` 关联到对应的排课方案
- 冗余存储 `teacher_id`, `class_id`, `subject_id` 便于查询，避免频繁 JOIN
- 唯一约束确保同一班级同一时间不会冲突

### 1.3 TeachingTask（教学任务）

**位置**: `backend/app/modules/tasks/models.py`

```python
class TeachingTask(Base):
    """教学任务数据模型"""
    __tablename__ = "teaching_tasks"
    
    id = Column(Integer, primary_key=True, index=True)
    teacher_id = Column(Integer, ForeignKey("teachers.id"), nullable=False)
    class_id = Column(Integer, ForeignKey("classes.id"), nullable=False)
    subject_id = Column(Integer, ForeignKey("subjects.id"), nullable=False)
    
    weekly_hours = Column(Integer, nullable=False, default=2)  # 周课时数
    
    # 连堂设置
    is_continuous = Column(Boolean, default=False)  # 是否需要连堂
    continuous_count = Column(Integer, default=2)  # 连堂节数
    
    layer_group_id = Column(Integer, ForeignKey("layer_groups.id"), nullable=True)
    preferred_period = Column(String(20), nullable=True)  # 优先时段：MORNING/AFTERNOON
    note = Column(String(200), nullable=True)  # 备注
```

**关键字段说明**:
- `is_continuous`: 布尔值，标记该任务是否需要连堂
- `continuous_count`: 连堂节数，默认 2 节
- **连堂逻辑**: 
  - 如果 `is_continuous=True` 且 `continuous_count=2`，则每周 6 课时需要排 3 次（每次 2 节）
  - 如果 `is_continuous=False`，则每周 6 课时需要排 6 次（每次 1 节）

## 2. 排课引擎架构

### 2.1 ScheduleEngine（总控引擎）

**位置**: `backend/app/engine/core.py`

**核心职责**:
1. 加载排课数据（教师、班级、科目、任务、分层组、场地）
2. 调用 CP-SAT 求解器生成排课方案
3. 保存结果到数据库
4. 计算方案评分和统计信息

**主要方法**:

```python
def run(
    self,
    optimization: int = 3,      # 优化程度 (1-5)
    plan_count: int = 1,         # 生成方案数量 (1/3/5)
    scope: str = "all",         # 排课范围
    grades: List[str] = None,    # 指定年级
    class_ids: List[int] = None, # 指定班级
    keep_manual: bool = False   # 是否保留手动调整
) -> Union[Dict[str, Any], List[Dict[str, Any]]]
```

**执行流程**:
1. 调用 `load_schedule_data(db)` 加载数据
2. 创建 `CPScheduleSolver` 实例
3. 调用 `solver.solve(time_limit_seconds, num_solutions=plan_count)`
4. 对每个方案调用 `_save_results()` 保存到数据库
5. 调用 `_build_summary()` 构建结果摘要
6. 返回方案列表（按得分排序）

### 2.2 CPScheduleSolver（CP-SAT 求解器）

**位置**: `backend/app/engine/solver/cp_solver.py`

**核心组件**:

#### 2.2.1 ScheduleSession（排课决策单元）

统一抽象分层组和普通任务为 Session：
- **分层组**: 每个 occurrence 是一个 Session，包含组内所有教师和班级
- **普通任务**: 每个 session 是一个 Session，只有 1 个教师和 1 个班级

```python
@dataclass
class ScheduleSession:
    id: int
    task_ids: List[int]          # 关联的任务ID列表
    teacher_ids: List[int]       # 涉及的教师ID列表
    class_ids: List[int]         # 涉及的班级ID列表
    subject_id: int
    subject_name: str
    duration: int                # 持续节数（连堂课 > 1）
    venue_type: Optional[str]    # 所需场地类型
    layer_group_id: Optional[int] # 分层组ID
    grades: List[str]            # 适用年级
    is_main_subject: bool = False
```

#### 2.2.2 SessionBuilder（会话构建器）

将 `Task` 和 `LayerGroup` 转换为统一的 `ScheduleSession` 列表：

1. **处理分层组**:
   - 获取分层组的所有任务
   - 根据 `weekly_hours` 和 `duration` 计算需要多少个 occurrence
   - 为每个 occurrence 创建一个 Session

2. **处理普通任务**:
   - 排除已被分层组覆盖的任务
   - 根据任务的 `sessions_count` 创建多个 Session
   - 连堂课：`sessions_count = weekly_hours // continuous_count`

#### 2.2.3 硬约束（Hard Constraints）

1. **H1**: 每个 Session 恰好安排到一个槽位
2. **H2**: 同一教师在同一 (day, period) 最多 1 节课
3. **H3**: 同一班级在同一 (day, period) 最多 1 节课
4. **H4**: 场地容量限制（如体育场同时只能容纳 N 个班）
5. **H5**: 每个班级每天同一科目最多 2 节课时

#### 2.2.4 软目标（Soft Objectives）

1. **主科优先上午**: 权重 40
2. **科目分散**: 同一天同班同科目尽量少，权重 -15
3. **教师课程紧凑**: 减少空窗期，权重 2

#### 2.2.5 求解流程

```python
def solve(time_limit_seconds, num_solutions) -> List[List[ScheduleRecord]]:
    # 1. 构建 sessions
    builder = SessionBuilder(self.data)
    self.sessions = builder.build()
    
    # 2. 构建索引（教师、班级、场地）
    self._build_indexes()
    
    # 3. 创建变量 x[session_id][(day, period)] = BoolVar
    self._create_variables()
    
    # 4. 添加硬约束
    self._add_hard_constraints()
    
    # 5. 添加软目标
    self._add_soft_objectives()
    
    # 6. 求解（支持多方案）
    solutions = self._run_solver(time_limit_seconds, num_solutions)
    
    return solutions
```

**多方案生成机制**:
- 第一个方案：正常求解
- 后续方案：重建模型并添加多样性约束，避免与之前方案完全相同
- 多样性约束：要求至少 10% 的 Session 分配不同

**容错机制**:
- 如果首次求解失败（INFEASIBLE），尝试放松约束：
  1. 移除 H5（每日同科目上限）
  2. 如果仍失败，只保留 H1+H2+H3（最小约束集）

## 4. 多方案存储机制

### 4.1 方案生成

当 `plan_count > 1` 时，求解器会生成多个方案：

```python
# core.py: _save_results()
for i, records in enumerate(solutions):
    suffix = f"_方案{chr(65 + i)}" if plan_count > 1 else ""
    schedule_id = self._save_results(records, suffix)
    # 方案A, 方案B, 方案C...
```

每个方案都会：
1. 创建一个新的 `Schedule` 记录（名称带后缀：`课表_20250206_143022_方案A`）
2. 创建对应的 `ScheduleItem` 记录
3. 计算评分和统计信息

### 4.2 方案选择

- 所有方案都保存在数据库中
- 通过 `is_active` 标记当前使用的方案
- 用户可以通过 API 激活任意方案
- 方案按得分排序，第一个为推荐方案（`recommended: true`）

### 4.3 方案对比

前端可以通过以下方式对比方案：
1. 获取所有方案列表（`GET /api/v1/schedules/`）
2. 获取每个方案的详情和统计信息
3. 比较 `score`, `teacher_gaps`, `main_morning_rate` 等指标

## 5. 完整数据流程

### 5.1 API 调用到求解器执行

```
1. 前端调用 POST /api/v1/schedules/generate
   ↓
2. router.py: generate_schedule()
   - 解析请求参数 (ScheduleRequest)
   - 创建 ScheduleEngine 实例
   ↓
3. core.py: ScheduleEngine.run()
   - 调用 load_schedule_data(db) 加载数据
   - 创建 CPScheduleSolver 实例
   ↓
4. cp_solver.py: CPScheduleSolver.solve()
   - SessionBuilder.build() 构建 Session 列表
   - _create_variables() 创建 CP-SAT 变量
   - _add_hard_constraints() 添加硬约束
   - _add_soft_objectives() 添加软目标
   - _run_solver() 调用 OR-Tools 求解器
   ↓
5. cp_solver.py: _extract_solution()
   - 从求解器提取 ScheduleRecord 列表
   - 返回 List[List[ScheduleRecord]]
```

### 5.2 结果保存到数据库

```
6. core.py: _save_results(records, suffix)
   - 创建 Schedule 记录
   - 为每个 ScheduleRecord 创建 ScheduleItem
   ↓
7. 数据库提交
   - db.add(schedule)
   - db.add(item) for each ScheduleItem
   - db.commit()
```

### 5.3 结果摘要构建

```
8. core.py: _build_summary(records, schedule_id)
   - 计算基础统计（总任务数、已排课数、失败数）
   - _calc_teacher_gaps() 计算教师空窗期
   - _calc_main_morning_rate() 计算主科上午率
   - _calc_continuous_rate() 计算连堂完整率
   - _calc_score() 计算综合得分
   ↓
9. 返回结果给前端
   - 单方案：返回 Dict
   - 多方案：返回 List[Dict]，按得分排序
```

### 5.4 数据模型转换流程

```
数据库 ORM 模型
    ↓ (DatabaseLoader.load())
引擎内部模型 (ScheduleData)
    ↓ (SessionBuilder.build())
ScheduleSession 列表
    ↓ (CP-SAT 求解)
ScheduleRecord 列表
    ↓ (_save_results())
数据库 ORM 模型 (Schedule + ScheduleItem)
```

## 7. 连堂课处理机制

### 7.1 TeachingTask 模型

```python
is_continuous: bool = False      # 是否需要连堂
continuous_count: int = 2        # 连堂节数
```

### 7.2 连堂逻辑计算

**位置**: `backend/app/engine/data/models.py` - `Task` 类

```python
@property
def sessions_count(self) -> int:
    """计算需要排几次课"""
    if self.is_continuous and self.continuous_count > 1:
        # 连堂课：每次排 continuous_count 节
        return self.weekly_hours // self.continuous_count
    return self.weekly_hours

@property
def session_duration(self) -> int:
    """每次课的时长（节数）"""
    if self.is_continuous and self.continuous_count > 1:
        return self.continuous_count
    return 1
```

**示例**:
- 周 6 课时，`is_continuous=True`, `continuous_count=2` → 需要排 3 次（每次 2 节）
- 周 5 课时，`is_continuous=False` → 需要排 5 次（每次 1 节）

### 7.3 连堂约束

**位置**: `backend/app/engine/solver/cp_solver.py`

1. **不跨午休**: 连堂不能跨第 5-6 节边界
2. **不跨 9-10 节**: 连堂不能跨第 9-10 节边界（除非是 G8/G9 周四）
3. **连续节次**: 连堂必须安排在连续的节次

## 8. 评分机制

### 8.1 综合得分计算

**位置**: `backend/app/engine/core.py` - `_calc_score()`

**评分规则**（总分 100 分）:

1. **排课完成率** (40 分)
   - 已排课任务数 / 总任务数 × 40

2. **主科上午率** (20 分)
   - 主科上午节数 / 主科总节数 × 20

3. **教师空窗期** (20 分)
   - 0 个空窗期: 20 分
   - < 5 个: 16 分
   - < 10 个: 12 分
   - < 20 个: 8 分
   - < 40 个: 4 分
   - ≥ 40 个: 0 分

4. **连堂完整性** (20 分)
   - 完整连堂任务数 / 总连堂任务数 × 20

## 9. 总结

### 9.1 数据模型层次

1. **数据库层**: `Schedule`, `ScheduleItem`, `TeachingTask` (SQLAlchemy ORM)
2. **引擎层**: `ScheduleData`, `Task`, `ScheduleRecord` (纯 Python dataclass)
3. **求解器层**: `ScheduleSession` (CP-SAT 决策单元)

### 9.2 关键特性

1. **多方案支持**: 可以生成多个方案并全部保存，通过 `is_active` 选择使用
2. **连堂处理**: 通过 `is_continuous` 和 `continuous_count` 字段控制
3. **分层组支持**: 统一抽象为 Session，支持复杂的分层/合班场景
4. **容错机制**: 求解失败时自动放松约束重试
5. **评分系统**: 综合考虑完成率、主科分布、教师空窗期、连堂完整性

### 9.3 数据流向

```
API Request → Router → ScheduleEngine → CPScheduleSolver → OR-Tools
                                                              ↓
Database ← ScheduleItem ← ScheduleRecord ← Solution Extraction
```
