# 手动排课增强方案

> 创建日期：2026-02-06
> 状态：已实施完成 (2026-02-06)
> 关联页面：`TimetableView.vue`（课表管理）

---

## 一、需求概述

当前课表管理页面仅支持基础的拖拽调课，存在三个核心不足：

| # | 需求 | 当前状态 |
|---|------|---------|
| F1 | 调课后约束违反反馈 | 无任何提示，用户不知道调课是否合理 |
| F2 | 手动锁定课程位置 | 按钮存在但点击只显示"开发中" |
| F3 | 调换时可用位置提示 | 对话框内容为空，无冲突分析 |

---

## 二、详细需求分析

### F1：约束违反实时反馈

**目标**：课表展示时，对当前存在约束违反的单元格进行可视化标记。

**交互设计**：
- **红框 + 红色角标**：违反硬约束（Tier 1/2），如教师冲突、班级冲突、同科目日超 2 节
- **橙框 + 橙色角标**：违反软约束（Tier 3），如主科未排在上午、艺体排在第一节
- **鼠标悬停 Tooltip**：显示具体违反的约束列表，例如：
  ```
  ⛔ 教师 Shane 在周二第3节存在冲突（与 IG8-2 数学冲突）
  ⚠ 主科「数学」排在下午（建议上午）
  ```
- **角标数字**：如一个单元格同时违反多条约束，角标显示数量

**需要检测的约束**：

| 约束 | 层级 | 检测逻辑 | 严重度 |
|------|------|---------|--------|
| 教师时间冲突 | Tier 1 | 同一教师在同一 (day, period) 被排了多节课 | 硬 (红) |
| 班级时间冲突 | Tier 1 | 同一班级在同一 (day, period) 被排了多节课 | 硬 (红) |
| 分层组不同步 | Tier 1 | 同一 layer_group_id 的任务未排在同一 (day, period) | 硬 (红) |
| 场地超容量 | Tier 1 | 同一场地类型同时使用数量超过场地总数 | 硬 (红) |
| 同科目日超 2 节 | Tier 2 | 某班某天同一科目排了 3 节及以上 | 硬 (红) |
| 主科未排上午 | Tier 3 | 主科排在 period >= 6 | 软 (橙) |
| 艺体排第一节 | Tier 3 | 艺体类科目排在 period == 1 | 软 (橙) |
| 科目分布不均 | Tier 3 | 某科目周内分布过于集中（如连续 3 天都排了） | 软 (橙) |

**技术方案**：

```
┌─────────────┐    GET /schedules/{id}/validate    ┌─────────────┐
│  Frontend    │  ─────────────────────────────▶    │  Backend     │
│  TimetableView│  ◀─────────────────────────────  │  Validator   │
│              │    { violations: { "3-5": [...] } }│  Service     │
└─────────────┘                                     └─────────────┘
```

#### 后端：新增 `ScheduleValidator` 服务

位置：`backend/app/engine/validator.py`（新文件）

```python
class ScheduleValidator:
    """课表状态验证器 - 检测当前课表中的约束违反"""

    def validate(self, schedule_id: int, db: Session,
                 class_id: int = None) -> dict:
        """
        返回格式:
        {
            "violations": {
                "3-5": [
                    {
                        "type": "teacher_conflict",
                        "tier": 1,
                        "severity": "hard",
                        "message": "教师 Shane 时间冲突（与 IG8-2 数学）"
                    }
                ],
                ...
            },
            "summary": {
                "hard_count": 2,
                "soft_count": 5,
                "score": 85
            }
        }
        """
```

**核心检测方法**（按优先级排列）：

1. `_check_teacher_conflicts()` — 按 (teacher_id, day, period) 分组，>1 即冲突
2. `_check_class_conflicts()` — 按 (class_id, day, period) 分组
3. `_check_layer_sync()` — 同一 layer_group_id 的任务是否在同一时间
4. `_check_venue_capacity()` — 按 (venue_type, day, period) 统计并发数
5. `_check_daily_subject_limit()` — 按 (class_id, subject_id, day) 统计
6. `_check_soft_violations()` — 主科上午、艺体首节等

#### 前端渲染

```vue
<div class="schedule-cell"
     :class="{
       'violation-hard': hasHardViolation(period.num, day),
       'violation-soft': hasSoftViolation(period.num, day)

  <div v-if="getViolations(period.num, day).length"
       class="violation-badge"

    {{ getViolations(period.num, day).length }}
  </div>
</div>
```

### F2：手动锁定课程

**目标**：用户可锁定某个课程位置，锁定后不可被调课/自动排课移动。

**交互设计**：
- 点击课程 → 详情对话框 → 点击"锁定位置"
- 锁定后单元格右上角显示 🔒 图标
- 再次点击可解锁
- 拖拽锁定课程时提示"已锁定，无法移动"
- 锁定课程作为 swap 目标时后端拒绝

**数据库变更**：

```sql
ALTER TABLE schedule_items ADD COLUMN is_locked BOOLEAN DEFAULT FALSE;
```

**后端变更**：

```python
# 新增：锁定/解锁 API
@router.put("/{schedule_id}/items/{item_id}/lock")
def toggle_lock(schedule_id, item_id, locked: bool = True, db = ...):
    ...

# 修改：swap 端点增加锁定保护
@router.post("/{schedule_id}/swap")
def swap_schedule_items(...):
    if item1 and item1.is_locked:
        raise HTTPException(400, "源课程已锁定")
    if item2 and item2.is_locked:
        raise HTTPException(400, "目标课程已锁定")
```

**前端变更**：
- 课表数据增加 `itemId` 和 `isLocked` 字段
- 详情对话框按钮绑定锁定 API
- 单元格渲染锁定图标

**关联改动**：`cp_solver.py` 需读取 `is_locked` 将锁定课程固定（不参与求解）。

### F3：调换时可用位置分析

**目标**：选择课程后点击"调换位置"，系统分析所有时间段的可用性。

**交互设计**：

调换对话框改为 **5×11 课表网格**，每格标注状态：

| 状态 | 颜色 | 含义 |
|------|------|------|
| 🟢 可用 | 绿色底 | 无冲突可放置 |
| 🟡 有风险 | 黄色底 | 可放但会违反软约束 |
| 🔴 不可用 | 红色底 | 硬约束冲突 |
| ⬜ 已占用 | 灰色底 | 有课程，可交换（需检查对方冲突） |
| 🔒 已锁定 | 深灰底 | 不可操作 |

鼠标悬停显示具体原因。

**后端 API**：

```python
@router.get("/{schedule_id}/swap-candidates")
def get_swap_candidates(
    schedule_id: int,
    day: int, period: int, class_id: int,
    db: Session = Depends(get_db),
):
    """
    返回:
    {
        "source": { "day": 3, "period": 2, "subject": "数学" },
        "candidates": {
            "1-1": {
                "status": "available",     // available|conflict|soft_risk|locked|occupied
                "current_subject": null,
                "conflicts": [],
                "warnings": []
            },
            "1-2": {
                "status": "conflict",
                "current_subject": "英语",
                "conflicts": ["教师 Shane 时间冲突"]
            },
            ...
        }
    }
    """
```

**检测逻辑**（每个候选位置）：

1. **教师冲突**：源课教师在目标时段是否有其他课
2. **分层组限制**：分层课暂标记为"不可单独调换"
3. **交换双向检查**：若目标有课，还检查对方移到源位置是否冲突
4. **锁定检查**：目标位置是否已锁定
5. **软约束检查**：主科上午、艺体首节等

**前端**：

```vue
<el-dialog v-model="showSwapDialog" title="选择调换目标" width="800px">
  <div class="swap-grid">
    <div class="swap-header">
      <div class="swap-time-col">时间</div>
      <div class="swap-day-col" v-for="d in 5">
        周{{ ['一','二','三','四','五'][d-1] }}
      </div>
    </div>
    <div class="swap-row" v-for="p in maxPeriods" :key="p">
      <div class="swap-time-col">第{{ p }}节</div>
      <div class="swap-candidate"
           v-for="d in 5" :key="d"
           :class="getCandidateClass(d, p)"
           @click="selectCandidate(d, p)">
        <el-tooltip :content="getCandidateTooltip(d, p)">
          <div class="candidate-content">
            {{ getCandidateLabel(d, p) }}
          </div>
        </el-tooltip>
      </div>
    </div>
  </div>
</el-dialog>
```

## 六、风险和注意事项

1. **性能**：`validate` 需加载整表所有 items 做交叉检查。建议支持 `class_id` 过滤、加内存缓存、前端防抖。

2. **分层课**：分层课调换涉及多班同步移动，F3 阶段暂标记为"不可单独调换"，后续可扩展。

3. **锁定与自动排课**：`cp_solver.py` 需读取 `is_locked`，将锁定课程固定到对应 slot 不参与求解。

4. **状态一致性**：调课后需同时刷新课表 + 违反数据，建议后端 swap 响应中直接返回更新后的违反状态。
